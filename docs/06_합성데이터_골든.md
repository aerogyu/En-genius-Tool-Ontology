# 06. 합성 데이터와 골든 기대값 (M2)

M3 적재·M4 도출이 맞는지 판정하는 **시험 데이터와 정답**이다. 실제 조사 데이터가 아니다 — 툴 이름은 공개 상용 툴이나
'가상-' 접두 가상 툴만, 인명은 가명 토큰(OOO)만 쓴다 (CLAUDE.md 절대 규칙 1·2·5).

## 1. 구성

| 파일 | 내용 |
|---|---|
| `data/synthetic/survey_spec.yaml` | 선언형 명세 — 분야 8, 툴사용 34(+ 중복 1행), 툴 22, 입출력 77행. 행마다 사례 태그(`cases`) |
| `data/synthetic/survey/SW조사_<분야>_20260924.xlsx` | 명세로 원본 양식을 채운 분야별 조사 파일 8개 (작성안내 B26 파일명 규칙) |
| `src/engenius_onto/synth.py` | 생성기 — `python -m engenius_onto synth [--check]` |
| `tests/golden/oracle.py` | docs/02 4~7장 규칙의 **독립 참조 계산** (src 코드와 공유하지 않음) |
| `tests/golden/expected_head.yaml` | 골든의 손으로 쓴 부분 — 해석 I1~I31, Leo 확인 질문, 적재 기대값, 사례별 기대값 |
| `tests/golden/expected.yaml` | 골든 전체 = 머리말 + 참조 계산 집계 — `python tests/golden/make_expected.py` 로 만든다 |

다시 만들기: 명세를 고친 뒤 `python -m engenius_onto synth` → `python tests/golden/make_expected.py` → `pytest`.
난수가 없고 xlsx 내부 시각을 고정해, 같은 명세면 파일이 바이트까지 같다 (`synth --check` 와 테스트가 확인).

## 3. 검증 기록

1차 초안 뒤 독립 검토 5관점(규칙 재유도·사례 커버리지·엑셀 층·참조 계산 코드·데이터 규칙) + 관점별 반박 검증.

- **규칙 재유도 검토자가 참조 계산을 보지 않고 엑셀에서 직접 다시 계산 — 골든 값 불일치 0건.**
- 지적 60건 중 58건이 반박을 통과했고, 대부분은 "골든이 잘못된 구현을 걸러내지 못하는 빈틈"이었다. 예: 착수 등급의
  조작 방식 분기·C 등급이 결과를 가르지 않음, D1-2 펼치기 판별 불가, 같은 툴·같은 툴사용 분기 미검증, 헤더·필수값·목록 밖 값
  사례 부족, 인명 누출 검사 토큰이 D6 값과 겹침. → 위 2장의 사례 추가로 전부 판별 가능하게 만들었다.
- docs/02 와 모순 1건: 1차 골든이 예시 행 판별에 '예시 위치' 조건을 넣었다 → 위치 무관 '적재 열 전체 일치' 로 바꾸고
  docs/02 2장에 반영 (실제 SANTA 응답은 비고 문구가 달라 보호된다).
- 참조 계산의 잠재 결함(실데이터에서만 드러날 표기): 확장자 'n/a' 분할, 사내 아닌 괄호 주석, 연계 SW '-'·'없음' 이 누락
  후보가 됨, 비고 두 개를 이어 붙여 가짜 키워드, 자기 자신 쌍, 동률 순서 의존, NFKC 가 'ㆍ' 를 바꿔 구분자 인식 실패
  → 고치고 `tests/test_oracle_rules.py` 로 잠갔다.

## 4. 한계와 Leo 확인 질문

- 합성 파일은 openpyxl 로 만들어 B 열 수식 캐시값이 없다. 실제 회신 파일(Excel 저장본)과 다르므로 적재기는 B 열 값과
  데이터 유효성을 쓰지 않는다 (expected loader.excel_layer_notes).
- 'SW ID·SW명은 예시와 같고 나머지가 다른' 실제 SANTA 응답 사례는 합성 데이터에 SANTA 를 새로 쓰지 않기 위해 넣지 않았다
  — M3 단위 테스트에서 예시 값을 바꿔 시험한다.
- 확인 질문 3건 (expected open_questions): Q-R1 같은 분야 재발송 파일 처리, Q-D2 신고하지 않은 상대에게 번진 수기 신호,
  Q-I3 비고 신호 구간의 착수 순위 표시.
