# 02. 툴 온톨로지 설계 명세

구현의 기준 문서다. 여기서 정하지 않은 세부는 구현자가 합리적으로 정하되, **바뀐 설계는 이 문서에 반영**하고 Leo에게 알린다.

## 0. 용어

| 한국어 | 식별자 | 뜻 |
|---|---|---|
| 분야 | `Field` | 연구소 24개 분야. 조직 노드 |
| 툴 | `Tool` | 제품 단위 툴 (중복 통합된 것). 예: ANSYS Fluent |
| 툴사용 | `ToolUsage` | 분야별 응답 1건 = SW기본정보 1행 = SW ID 1개 |
| 입출력 | `IOSpec` | SW입출력 1행. 한 툴사용이 받거나 내놓는 데이터 1종 |
| 데이터분류 | `DataCategory` | 분류 드롭다운 값 (설계-도면, 설계-2D Layout, 해석-결과 …) |
| 공급연결 | `Feed` | 규칙으로 계산한 A 출력 → B 입력 연결 (파생) |
| 공급한다 | `eg:feeds` | 툴사용 → 툴사용 지름길 관계 (경로 질의용, 파생) |

## 1. 목표와 역량 질문(CQ)

이 온톨로지가 답해야 할 질문이다. 각 CQ는 `queries/cqNN_*.rq`로 구현하고 보고서 시트로 낸다.

| CQ | 질문 | 용도 |
|---|---|---|
| CQ01 | 특정 툴사용의 상류·하류 (1단계) 와 체인 (n단계) | 툴 체인 파악 |
| CQ02 | 수기로 이어진 구간 전체 | 자동화 후보 |
| CQ03 | 착수 가능 구간 (착수 등급 A/B/C, 정렬) | **에이전트 개발 대상 선정 — 핵심** |
| CQ04 | 계산된 연결 vs 신고된 연결 대조 | 확정·숨은변환·잠재 판정 |
| CQ05 | 고립 툴사용 (입출력 미기재 / 무연결) | 조사 보완 대상 |
| CQ06 | 특정 (분류, 확장자) 데이터가 바뀌면 영향받는 하류 전체 | 영향 범위 |
| CQ07 | 분야 간 연결 매트릭스 (전체 / 수기) | 경영 보고용 한 장 |
| CQ08 | 허브 툴 (연결 수 상위) | 참고용 — 순위 산정에서 제외 |
| CQ09 | 연계 SW명에는 나오지만 조사에 없는 툴 | 조사 누락 후보 |
| CQ10 | 툴 표기 변형과 통합 후보 | 사람 검토 (HITL) |

## 2. 원천 데이터

전체 열·안내·드롭다운은 `reference/양식_명세.md`에 있다. 핵심만 요약한다.

- 시트 2개를 적재한다: **SW기본정보**(33열), **SW입출력**(13열). '선택지' 시트는 드롭다운 값 검증용으로 읽는다.
- **SW ID는 툴 ID가 아니라 분야별 사용 기록 ID다.** 같은 툴을 여러 분야가 적으면 SW ID도 여러 개다 → `Tool`과 `ToolUsage`를 나누는 이유.
- 입출력은 분야마다 다르므로 `ToolUsage`에 붙는다.
- 실제 사내 양식은 원본과 다르다 (분야 24개, 분류 값 추가, 헤더 문구 변경 가능). 그래서 **헤더 이름으로 매핑**하고 **드롭다운 값은 입력 파일의 '선택지' 시트에서 읽는다.**
- 'SW명(자동)' 열은 수식이므로 무시한다. SW명은 SW ID로 SW기본정보에서 찾는다.
- **'실무 문의처' 열은 읽지도 저장하지도 않는다** (인명).
- 예시 행: SW기본정보 4행, SW입출력 4~6행. 작성안내는 '5행부터'라고 했으므로 응답자가 예시를 덮어썼을 수 있다 → **행 번호가 아니라 템플릿 예시 값과의 일치로** 판별한다 (`config/template_examples.yaml`). 일치 = 적재 열 전체(B 'SW명(자동)' 수식·K '실무 문의처' 제외)가 예시 행과 같음 — 위치와 무관하다. 예시의 비고 문구까지 같아야 하므로 SW ID·SW명만 같은 실제 응답(예: SAS-01=SANTA)은 제외되지 않는다 (M2 골든 I15). 제외한 행은 사유와 함께 로그에 남긴다.
  **예시와 거의 같은 행** (docs/09 #3 A, I15 개정 2026-10-12): 예시를 한두 칸 고쳐 남긴 행은 정확히 같지 않아 응답으로 들어온다 — 그래서 예시의 **정보 열**(예시 값이 비지 않고 빈 값 토큰(NA·모름 등, I16)도 아니며 그 파일에 있는 열; 5개(`example_near_min_cols`) 미만인 예시와는 비율을 보지 않음) 가운데 같은 칸 비율이 `rules.yaml loader.example_near_ratio`(0.8) 이상인 예시가 있거나 기본정보 비고가 예시 비고 문구와 같으면 경고 '예시와 거의 같은 행' + 수정 요청표 행을 남기고 **응답으로 적재**한다 (빼지 않는다 — 예시를 고쳐 실제 답으로 쓴 파트가 답을 잃지 않게). 빈 값 토큰 칸을 빼는 이유: 양식 v1.1 TA-01 예시는 절반이 NA·모름이라 NA 투성이 실제 응답이 0.80~0.83 으로 걸렸다 (합성 응답 최고 0.633, 예시 한 칸 수정 0.857 이상). 같은 Tool ID 의 진짜 행이 뒤에 있으면 진짜 행을 쓴다 (5장 4). 한 시트에 예시 유사 행만 있고 정확한 예시가 0 이면 파일·시트마다 '예시 행 판별 설정 점검' 경고 — 예시를 고쳐 남긴 것이 아니면 그 파일의 양식판 예시가 설정과 다른 것이니, 사내 양식판의 예시를 `template-examples --form <양식> --overlay` 로 사내 오버레이(`data/real/config/template_examples.yaml`, 저장소 예시와 시트별 합집합)에 더한다.

## 3. 클래스 모델

| 클래스 | 원천 | 식별자 | 주요 속성 | 관계 |
|---|---|---|---|---|
| `Field` | SW기본정보 '담당 부서' 값 | `FLD-001` | 이름, 상태 | `succeeded_by` → Field (통폐합·분할 승계) — 스키마·파이썬 이름은 `ResearchField` (RDF 클래스는 `eg:Field`, §12) |
| `Tool` | SW명(정식)·제조사·구분 (통합 후) | `TOOL-000001` | prefLabel, altLabel(변형 표기), vendor, kind | — |
| `ToolUsage` | SW기본정보 1행 | `USE-000001` | source_key(SW ID 원문) 외 `reference/양식_명세.md`의 매핑 열 전부 | `usage_field` → Field, `usage_tool` → Tool |
| `IOSpec` | SW입출력 1행 | `IO-<해시>` | direction, data_name, extensions(정규화 목록), extensions_raw, inhouse_format, format_standard, data_nature, transfer_method, partner_raw, storage_path, security_grade, note | `io_owner` → ToolUsage, `io_category` → DataCategory, `partner_tools` → Tool (0..n) |
| `DataCategory` | 분류 값 | `CAT-001` | 이름 | — |
| `Feed` (파생) | 규칙 계산 | `FEED-<해시>` | matched_category, matched_extensions, confidence, declared, transfer, manual, manual_basis, grade, rule_version | `from_io`, `to_io`, `supplier`, `consumer` |
| `SurveyLoad` | 적재 1회의 원천 파일 1개 (파일마다 1건, 같은 실행은 `run_id` 공유 — §12) | `LOAD-<일시>-<순번>` | 실행 ID, 원천파일명(경로 아님), sha256, 적재일시, 행 수, 제외 행 수, 경고 수 | — |

- 드롭다운 값을 담는 속성은 LinkML 열거형으로 문서화하되, **목록에 없는 값이 와도 적재를 막지 않고 경고로 보고한다** (실제 양식이 바뀌었을 수 있음).
- 숫자 열(사용 인원수, 보유 수량)은 정수로 변환하고, 실패하면 원문을 보존하고 경고한다.
- 향후 확장용 예약: `WbsTask` —`uses_tool`→ `ToolUsage`/`Tool` (PoC의 WBS Lv.6 연결). 지금은 구현하지 않는다.

## 4. 식별자·네임스페이스·레이블

- 네임스페이스(임시, 스키마 `schema/engenius_tool.yaml` 의 prefixes 한 곳에서 일괄 변경 — 코드는 거기서 읽는다. 바꾼 뒤 `python -m engenius_onto schema` 로 재생성, §12): `eg:` = `http://en-genius.local/onto/` (클래스·속성), `egid:` = `http://en-genius.local/id/` (인스턴스)
- `FLD`·`TOOL`·`USE`·`CAT` ID는 **레지스트리 CSV**로 관리해 재적재해도 같은 ID를 유지한다. 레지스트리는 데이터 옆에 둔다: `data/synthetic/registry/`, 사내에서는 `data/real/registry/`. **합성용 레지스트리를 사내 실데이터에 재사용하지 않는다.**
- `IO`·`FEED` ID는 결정적 해시 (sha1 앞 10자리). IO: (USE ID, 방향, 데이터 명칭, 분류 CAT ID, 확장자 원문, 전달 방법, 연계 SW명 원문) — 같은 데이터를 상대별로 두 행에 적어도 합쳐지지 않게 전달 방법·연계 SW 를 넣는다 (D2). 정규형: 필드마다 NFC + 앞뒤 공백 제거, 구분자 ``, sha1 16진 소문자. 그래도 키가 같은 완전 중복 행은 경고하고 두 번째부터 행 순번을 덧붙인다. FEED: (from_io 전체 IRI, to_io 전체 IRI).
- **USE 레지스트리 키는 (분야 FLD ID, SW ID)** 다 (D3). SW ID 는 부서가 매기므로 분야가 다르면 같은 SW ID 가 있을 수 있다. 원천 파일명은 키에 넣지 않는다 — 재발송 때 파일명이 바뀌어도 USE ID 가 유지되게. **파일 간 같은 (파트, SW ID) 충돌 때만** 전용 파일이 아닌 쪽 SW ID 에 구분 꼬리 `@<파일 약칭>`(규칙 밖 파일은 `@file-<sha256 앞 10자>`)를 붙인다 (5장 4, 골든 I36) — 꼬리도 파일명이 아니다 (docs/09 C4). 규칙 밖 파일의 꼬리는 내용 해시라 내용이 바뀌면 새 USE ID 가 나온다 (파일명을 규칙대로 고치면 사라지는 대가).
- **레지스트리는 상태와 함께 전부 내보낸다** (D7): 레지스트리 CSV 에 `status` 열을 두고, 이번 적재에 나오지 않은 FLD·TOOL·CAT 는 `폐기` 로 survey 그래프에 계속 낸다. 폐기된 ID 는 재발급하지 않는다.
- 모든 노드에 `rdfs:label "…"@ko`. Tool은 `skos:prefLabel`(대표 이름)과 `skos:altLabel`(변형 표기들).
- SW ID 원문은 `source_key` 속성으로만 보존한다 (분야 약칭이 들어 있어 URI로 쓰지 않는다 — 조직 개편 시 의미가 깨짐).

## 5. 적재 규칙

1. `openpyxl`(`data_only=True`)로 읽는다. 2행을 헤더로 보고 `config/header_map.yaml`로 표준 필드명에 매핑한다. 헤더 비교 시 `*`와 공백은 무시한다. 매핑 안 된 헤더는 경고.
   사내 양식의 추가 문구는 오버레이 `data/real/config/header_map.yaml` 에 더한다 — 저장소 문구와 (시트, 슬롯)별 합집합, 시트 키는 v1.1 이름('Tool 입출력')도 된다.
   제외 열(실무 문의처·No.·자동 수식 열)이나 인명 열 낱말(문의처·담당자·연락처·작성자)이 든 문구·다른 슬롯의 기본 문구·두 슬롯에 같은 문구는 설정 오류 (I30 개정, 2026-10-12).
   **엑셀 층 신호 (I37, docs/09 7장 — 2026-10-12)**: 수식 결과 오류 셀(`#N/A`·`#REF!` 등)은 빈칸으로 보고 열마다 경고 '수식 오류 셀' + 행마다 수정 요청 (D4 예외 —
   오류 표기는 응답 값이 아니다; Tool ID 칸이 오류면 그 행은 제외하고 입출력은 이어받기(I22)도 하지 않는다), 캐시 없는 수식(값 없이 수식만 — 엑셀에서 열어 저장하면 읽힘)은
   열마다 경고, 숨긴 행은 적재하고 시트마다 경고, 양식 밖 내용 있는 시트는 경고('양식 사본 시트' — 헤더가 양식과 같으면, 적재하지 않음; 아는 시트는 `rules.yaml loader.other_sheets`),
   적재한 툴사용이 0건인 파일은 경고 '툴사용 0건'.
2. SW ID가 빈 행은 건너뛴다. 연속 빈 행이 N개(설정)면 시트 끝으로 본다.
3. 예시 행은 내용 일치로 제외한다 (2장 참고).
4. 같은 SW ID가 **한 파일의** SW기본정보에 두 번 나오면 경고하고 먼저 나온 행을 쓴다 — 예외: 앞 행이 '예시와 거의 같은 행'(2장)이고 뒤 행은 아니면 앞 행을 빼고 뒤 행을 쓴다 (경고 '중복 SW ID — 예시 유사 행 제외', 수정 요청 '예시 행 남음'; 고쳐 남긴 예시가 진짜 응답을 밀어내던 문제, docs/09 #3 A·I15 개정 2026-10-12. 둘 다 예시 유사면 먼저 나온 행). 다른 파일(다른 파트)의 같은 SW ID 는 충돌이 아니다 — 둘 다 적재한다 (D3, 파트 키 v0.3 — 행의 '담당 부서' 는 키가 아니다). **적재하는 두 파일 이상에 같은 (파트, SW ID) 가 나오면** (묶음 파일 + 분할 전용 파일, 규칙 밖 파일끼리 등) 둘 다 적재하고 (파트, 파일 쌍)마다 경고 '파일 간 같은 (파트, Tool ID)' — 전용 파일(파일 약칭 = 행의 파트) 행 하나만 원래 키, 원문 SW ID 가 겹치는 나머지는 구분 꼬리(4장), 표기만 다르면 경고만 (골든 I36, docs/09 #1 (a) 2026-10-12). 규칙 밖 파일의 SW ID 가 규칙 안 파일과 겹치면 경고 '규칙 밖 파일의 Tool ID 가 다른 파일과 겹침' (이름이 틀린 재발송 의심 — 파일명을 고친다). 파일 분야가 같은 두 파일은 재발송이다 (5-1).
5. SW입출력의 SW ID 는 **같은 파일의** SW기본정보에서 찾는다. 없으면 경고 (고아 입출력) — io_owner 없이 owner_source_key 만 두고 적재한다.
5-1. 조사 응답은 분야별 파일로 오고 파일명에 분야 이름이 들어간다 (인명 없음, Leo 2026-09-24). **파일명 규칙 (Leo 확정 2026-09-28, 양식 v1.1 작성안내 B27 과 같음):** `Tool조사_<부서>_<YYYYMMDD>.xlsx` — ① 구분자는 `_` 두 개뿐 (부서명 안에 `_`·공백 금지, 괄호·하이픈은 허용: `2차유로(SAS)`), ② `<부서>` 는 그 파일 행들의 '담당 부서' 값(선택지 목록)과 글자 그대로 같게, ③ `<YYYYMMDD>` 는 그 파일(판)을 적재 폴더에 넣은 날 — Leo 2026-09-30 (재발송 판정에만 쓴다. 같은 파일 재적재 때는 바꾸지 않는다), ④ 그 밖의 꼬리(인명·사번·`(1)`·`최종`)와 `.xlsm` 금지 — 단 브라우저 사본 꼬리 `(n)`(앞 공백 허용, 숫자만)은 적재기가 사본 번호로 읽어 재발송 판정에 넣는다 (I31, 2026-10-12). ⑤ 한 파일에 여러 파트가 들면 묶음 약칭(예 `MD` = MDT+MDC)을 쓰고 행의 Tool ID 앞부분으로 파트를 나눈다 (`config/parts.yaml file_bundles`, 약칭 표는 docs/10 5장, 2026-09-30). 옛 접두어 `SW조사_`(v1.0 B26) 도 읽는다 (I31, `config/rules.yaml loader.file_name_regex`). 규칙 밖 파일은 분야 미상으로 적재되어 재발송 판정·담당 부서 대조를 못 한다 (docs/09 #8 A: 이름은 해시 `Tool조사_규칙밖_<sha256 앞 10자>.xlsx` 로만 기록 — 같은 내용 사본이 겹치면 `-2`·`-3`, 원래 이름은 어디에도 쓰지 않고 load_log 에 입력 순번 `index` 만). 파일명의 분야와 행의 '담당 부서' 가 다르면 경고한다. **재발송:** 같은 분야 파일이 둘 이상이면 (파일명 날짜, 사본 번호, 파일명) 이 가장 늦은 파일 하나만 적재하고 — 같은 날짜면 사본 `(n)` 번호가 큰 쪽(나중에 받은 파일) — 나머지는 적재하지 않고 '재발송으로 대체' 경고를 남긴다 (두 파일 내용이 같으면 끝에 '(내용 같음)'; Leo 결정 2026-09-24, 사본 2026-10-12, 골든 I33). 대체된 파일의 행은 제외 건수에 넣지 않는다. **같은 내용 파일:** 그 뒤 남은 파일 가운데 내용(sha256)이 같은 파일은 한 번만 적재한다 — 규칙 안 파일 우선, 다음 입력 순서; 나머지는 '같은 내용 파일: X = Y (한 번만 적재)' 경고, 제외 건수에 넣지 않는다 (I33).
5-2. 셀 타입 (D5): 문자열 슬롯에 숫자 셀이 오면 정수는 그대로 문자열로, 정수값 float 는 소수점 없이, 그 외 float 는 문자열로 바꾸고 **'엑셀 숫자 변환으로 값이 바뀌었을 수 있음'** 경고 (예: `5.10`→5.1, `2027.10`→2027.1). 정수 셀은 경고하지 않는다 — `01`→1 같은 선행 0 소실은 셀만 보고는 알 수 없는 한계다 (M2 골든 I27). 날짜 셀은 만료 시기면 YYYY-MM 으로, 그 밖의 문자열 슬롯이면 ISO 문자열 + 경고.
**만료 시기 문자열 (docs/09 #21 3단, I16·I27 — 2026-10-12)**: 텍스트 날짜(`2027.03`·`2027/3`·`2027-03-31`·`2027. 3. 31.`·`2027년 3월`)는 YYYY-MM 으로 바꾸고 경고
'만료 시기 표기 변환', `영구`(`rules.yaml loader.month_blank_values` — 양식 안내 '영구면 공란' 인데 v1.1 예시 행이 '영구')와 빈 값 토큰(NA·-·없음 등)은 빈칸(원문 없음, 파일당 한 줄
'빈 값 표기 만료 시기'), 그 밖 문자열은 원문 보존 + 경고 '만료 시기 형식 아님' + 수정 요청 '만료 시기 형식' (스키마 층은 계속 패턴 위반). 원래 셀이 **문자열**일 때만 —
실수 셀 `2027.1` 은 위 실수 규칙 그대로(문자열로 바꾼 뒤 정규화하면 2027-01 로 잘못 바뀐다). 값 대응표(`value_aliases.yaml`)에 원문을 적어 두면 대응표가 먼저 바꾼다.
드롭다운 칸의 빈 값 토큰(목록 밖 'NA'·'-')은 원문 보존·선택지 검사 제외·파일당 한 줄 (양식 v1.1 작성안내가 'NA' 를 정식 응답으로 안내 — I28 기록).
5-3. 자유 텍스트 인명 경고 (D6): 비고·애로 구간 등 자유 텍스트에 인명으로 보이는 패턴(직급어 + 내선·사번 형태 등, `config/rules.yaml` 에서 조정)이 있으면 경고한다. 자동 삭제는 하지 않는다 — 판단은 엔지니어.
6. LinkML 스키마로 인스턴스를 검증한다 (생성한 Pydantic 클래스 또는 LinkML 검증기). 필수값 누락·형식 오류·드롭다운 미등록 값은 **경고 보고**하고 적재는 계속한다. 어떤 행도 조용히 버리지 않는다. **값도 버리지 않는다** (D4): Pydantic 은 행 단위 오류 수집에만 쓰고, RDF 는 전용 작성기로 원문 리터럴 그대로 쓴다 — 목록 밖 값·형식 오류는 SHACL 위반(= 경고 보고서)으로 드러난다.
7. 결과는 survey 그래프(TTL)와 `SurveyLoad` 메타데이터로 낸다.

## 6. 정규화

### 6.1 툴 통합 (CQ10)
1. `config/tool_aliases.yaml`(대표 이름 ← 변형 표기들, 그리고 apply-review 가 쓰는 키 단위 판정 이력 `merge_pairs`·`merge_keys`·`labels`)을 먼저 적용한다. 사내 판정은 오버레이
   `data/real/config/tool_aliases.yaml` 에 쌓이고 저장소 파일 위에 합쳐진다 (aliases·distinct·merge_pairs 는 합집합 — docs/09 C15, 2026-10-02). 두 파일의 통합 관계는 추이적으로 닫는다.
   적재기는 `merge_pairs` 가 있으면 거기서 `merge_keys` 를 다시 계산해 쓴다 (손으로 고친 이력이 조용히 무시되지 않게; 파일의 `merge_keys` 와 다르면 경고 '손으로 고친 merge_pairs — merge_keys 재계산', 다음 apply-review 저장이 파일을 맞춘다). 이력 없이 `merge_keys` 만 있는 옛 파일은 그대로 읽는다.
2. 정규화 키: NFKC → 소문자 → 괄호 안 주석 제거 → 버전 토큰 제거(`v4.2`, `2024R1`, `R19`, `SP2`, `5.6.1`, 연도 `2016` 등) → 토큰 치환(`rules.yaml tool_token_map`: `C++`→`cpp`, `C#`→`csharp`) → 영숫자·한글 외 제거. 키가 제조사명으로 시작하면 떼어낸 나머지를 키로 쓴다 (`ansysfluent` + 제조사 ANSYS → `fluent`). 떼고 남는 것이 없으면 떼지 않는다 (툴명 = 제조사명, 예: Tecplot → `tecplot`).
   **제조사 접두 흡수** (Leo 결정 Q3(a), 2026-10-02): 제조사 칸이 비거나 달라도 키가 조사에 나온 어느 제조사명으로 시작하고 나머지가 다른 행의 툴 키와 같으면 그 툴로 흡수한다 (경고 '제조사 접두 흡수'; 별개 판정 쌍은 제외). 흡수된 옛 키의 레지스트리 행은 통합됨.
   흡수 쌍은 모든 행의 키를 정한 뒤 키 집합 위에서 구해 합집합으로 묶고 **그룹 단위**로 모든 행에 적용한다 (행 순서 무관; 셋 이상이 얽혀도 — `altairfluent`·`ansysfluent`·`fluent` — 쌍을 버리지 않고 한 그룹). **생존 키**는 그룹 안에 레지스트리 활성 행이 있는 키가 정확히 하나면 그 키(TOOL ID 유지 — 'Fluent' 행이 나중에 들어와도 기존 `ansysfluent` ID 가 흔들리지 않는다), 없으면 접두를 뗀 쪽 = 사슬의 끝(접두를 뗀 키의 대표 키; 별칭이 없으면 그룹에서 가장 짧은 키)이다 (경고에 방향·이유 표시; 골든 oracle 은 레지스트리를 모르므로 늘 사슬의 끝). **별개 판정 쌍이 든 그룹(제3의 키를 거쳐 묶인 경우)과 레지스트리 활성 키가 둘 이상인 그룹은 흡수하지 않고 검토표로 넘긴다** — 전자는 경고 '제조사 접두 흡수와 별개 판정이 충돌' 만(이미 판정한 쌍), 후자는 경고 '제조사 접두 흡수 보류: 기존 툴 둘 이상' 과 함께 그룹의 키 쌍을 사유 '제조사 접두' 로 `tool_review.csv` 에 올린다 (기존 툴 둘을 합치는 판정은 사람 몫, HITL — 2026-10-02). 범용 제조사(`generic_tool_names`, '자체개발' 등)는 같은 행에서 떼지도 접두 흡수·연계 SW명 해석에 쓰지도 않는다 (Q3(b)).
   **범용·빈 이름** (Leo 결정 Q3(b)): 키가 비거나 `rules.yaml generic_tool_names`('자체개발'·'사내툴'·'매크로' 등)이면 통합하지 않고 행별 키 `미상:<파트>/<Tool ID>` 로 별개 툴로 두며, 수정 요청표에 '툴 이름을 지어 주세요' 행을 싣는다 (분야마다 자체개발 툴이 달라 통합 불가). 연계 SW명에 적힌 범용 이름은 빈 값처럼 버린다.
3. 키가 같으면 같은 Tool. 키가 달라도 `difflib` 유사도 ≥ 임계값(기본 0.85)이거나 한쪽이 다른 쪽을 포함하면(짧은 키가 3자 이상일 때만 — `candidate_min_contain_len`) **통합 후보로만** 검토표에 올린다. 자동 통합하지 않는다. `미상:` 키는 후보에 올리지 않는다.
4. 같은 Tool인데 제조사·구분 응답이 엇갈리면 다수값을 쓰고 검토표에 표시한다.
5. 검토표의 '판정' 열에 사람이 적은 결과를 `tool_aliases.yaml`에 반영하는 명령을 제공한다 (HITL 루프). 통합은 툴A_키·툴B_키를 **판정 이력 `merge_pairs: [[A 키, B 키], ...]`** 에 쌓고(생존 키 = A 키, TOOL ID 유지; 대표 이름은 적었을 때만 판정 당시의 대표 키에 `labels[대표 키]` 로 — 라벨을 옮기거나 승계하지 않는다), `merge_keys[B 키] = 대표 키` 는 저장 때마다 이력에서 다시 계산한다 (대표끼리 이어 깊이 1, 같은 그룹이면 라벨만 갱신). **그룹의 대표 이름은 적재기가 고른다**: `labels[대표 키]` 가 있으면 그것, 없으면 그룹 키 가운데 이력에서 가장 최근에 A 키로 적힌 키의 라벨, 그다음 키 정렬 순 첫 라벨, 그것도 없으면 다수결 표기 — 그래서 통합(c=b 'Tool C')·통합(a=c 이름 없음) 뒤 그룹 이름은 'Tool C' 이고, 별개(a/c) 로 되돌리면 a 는 자기 이름(다수결)으로, c 그룹(b 포함)은 'Tool C' 로 돌아간다. 별개는 직접 쌍(어느 순서든)을 이력에서 지우고 다시 계산한 뒤 `distinct` 에 넣으며, 직접 쌍이 없는데 대표가 같은 간접 사슬은 오류(사람이 파일을 고친다) — 그래서 통합(c=b)·통합(a=c)·별개(a/c) 뒤 b 는 c 와만 통합으로 남는다. `merge_keys` 만 있는 옛 파일은 이력으로 승격해 읽는다. 되돌린 키의 통합됨 레지스트리 행은 같은 ID 로 되살아난다 (docs/09 #2·#14·C2, 2026-10-02). CSV 는 utf-8-sig → cp949 순으로 읽는다 (#15). 공개 별칭(`config/tool_aliases.yaml`)은 쓰는 곳이 `data/real/config` 이거나 `--with-public-aliases` 일 때만 사슬 검사에 섞는다 (독립 설정 사본에서는 섞지 않는다; `load --overlay <폴더>` 와는 다른 옵션). 설정 오버레이에서 값 없는 키(`loader:`)로 매핑·목록 기본값을 지우는 것은 설정 오류로 멈춘다 ('[NG] 설정 오류: … 값이 비어 있다').

### 6.2 확장자
- 소문자화, 앞의 `.`·`*` 제거, 구분자(`/ , ; ·` 와 **모든 공백 문자** — 줄바꿈·`\r` 포함, 설정과 관계없이)로 분리해 목록으로 만든다.
- **`형식명(.확장자)`** 처럼 괄호 안이 `.확장자`(점으로 시작, 여럿이면 구분자로 이음)뿐이면 괄호 안 확장자를 쓰고, 괄호 바로 앞의 한 단어(사이 공백 허용)는
  형식 이름으로 버린다 — `Excel(.xlsx)`→xlsx, `Parasolid (.x_t)`→x_t, `NASTRAN(.bdf, .f06)`→bdf·f06. 버린 이름에 `사내` 가 있으면 사내 표기(`사내(.dat)`).
  점 없는 괄호(`STEP(AP214)`·`.dat(ASCII)`)는 주석으로 뗀다. 여러 단어 형식명(`Microsoft Excel (.xlsx)`)은 앞 단어가 토큰으로 남는다 (docs/09 #10, 2026-10-12).
- `config/extensions.yaml`의 별칭 적용: `step→stp`, `iges→igs`, `jpeg→jpg`, `tif→tiff`, `yml→yaml` 등. 한글 표기: `엑셀→xlsx`, `워드→docx`, `파워포인트→pptx`, `한글→hwp`, `텍스트→txt`.
  영문 형식 표기: `excel→xlsx`, `word→docx`, `powerpoint→pptx` (`ppt`·`xls` 는 별개 확장자라 별칭이 아니다).
- 확장자 패턴에 맞아도 확장자가 아닌 말(`non_extension_tokens` — or·and·또는·file·ascii·binary·parasolid·ap214 등)과 **숫자만 있는 토큰**(`AP 214` 의 214, Leo 2026-10-12)은
  매핑 실패로 경고한다 (원문 보존, 수정 요청표 '확장자 확인'). 별칭이 이 목록보다 먼저라 사내 오버레이에 `parasolid: x_t` 를 주면 경고 대신 x_t 가 된다.
- 점으로 이은 토큰은 `compound_extensions`(tar.gz·cas.h5·dat.h5 등) 밖이면(`model.stp`) 값은 그대로 쓰고 경고 '확장자 다중 점 확인' 만 낸다.
- `(사내)`·`사내` 표기는 떼어내고 `inhouse_format=true`로 둔다.
- `없음`·`모름`·`-` 등은 빈 값. 매핑 못 한 표기는 원문을 보존하고 경고.

### 6.3 연계 SW명
- 구분자로 나눠 툴 통합과 같은 정규화 키로 Tool 레지스트리·별칭에 맞춘다.
- 맞춘 것은 `partner_tools`, 못 맞춘 것은 **조사 누락 후보**(CQ09)로 모은다 (언급 횟수, 언급한 분야 포함).

## 7. 연결 도출 규칙 (`rules/feed_v1.rq` 등, 버전 관리)

### 7.1 계산된 연결 (Feed)
출력 명세 `o`와 입력 명세 `i`에 대해 아래를 모두 만족하면 `Feed(o → i)`를 만든다.
- `o`는 생산, `i`는 소비 방향
- `o.io_category == i.io_category`
- `o.extensions ∩ i.extensions ≠ ∅` (한쪽이라도 확장자가 비면 연결하지 않고 '확장자 미기재'로 경고 — 경고는 확장자가 빈 입출력마다 1건, CQ04 에서는 그 입출력의 신고 상대를 '숨은변환 의심' 이 아니라 '확장자 미기재' 로 판정한다)
- `o.io_owner ≠ i.io_owner` (같은 툴사용끼리는 제외. 같은 Tool의 다른 분야 사용끼리는 허용)

그리고 지름길 `supplier eg:feeds consumer`를 함께 만든다.
- `confidence`: 겹친 확장자가 전부 범용 확장자(`config/rules.yaml`의 `generic_extensions`: xlsx·csv·txt·pdf·docx·pptx·hwp 등)면 `낮음`, 아니면 `보통`. 엑셀 상관식처럼 xlsx로 오가는 실제 체인이 있으므로 **범용 확장자를 제외하지 않고 신뢰도만 낮춘다.**

### 7.2 계산 vs 신고 대조 (CQ04)
단위는 (입출력 명세, 상대 Tool)이다. 입력 명세 `i`에 대해:
- 계산 상대 = `i`로 들어오는 Feed들의 공급 측 Tool 집합
- 신고 상대 = `i.partner_tools`

| 계산 | 신고 | 판정 |
|---|---|---|
| O | O | 확정 |
| X | O | **숨은변환 의심** — 신고 상대가 같은 분류·확장자 출력을 내지 않음. 누군가 중간에서 포맷을 바꾸는 중 |
| O | X | 잠재 — `partner_raw`가 비었으면 '잠재(연계 미기재)', 적었는데 빠졌으면 '잠재(신고와 다름)' |

출력 명세 `o`도 같은 방식으로 대조한다. `Feed.declared`는 어느 한쪽 신고와 일치하면 true.

### 7.3 수기 구간 (CQ02)
- `Feed.manual = true`: `i` 또는 `o`의 전달 방법이 `manual_transfer_values`(기본 `메일·수기 전달`)에 속할 때 → `manual_basis = 전달방법`.
  단, 그 수기 행이 연계 SW 를 적었으면 수기 신호는 **적힌 상대(해석된 툴)와의 Feed 에만** 적용한다 — 적힌 상대가 아닌 툴사용과는 Feed 가 있어도 수기가 아니다. 연계 SW 가 비었으면 모든 상대에 적용한다 (Leo 결정 2026-09-24 '우선 그렇게 해보자', 골든 I32 — 운영 중 놓치는 구간이 보이면 재검토).
- 보조 신호: 전달 방법은 아니지만 `i`·`o`의 비고에 `manual_note_keywords`(수기·수작업·손으로·복사·재입력)가 있으면 `manual_basis = 비고`로 따로 표시. 원본 양식 예시도 전달 방법은 '파일 저장'인데 비고에 'CATIA 치수 수기 추출'이 적혀 있다 — 숨은 수작업은 비고에 있다. 비고 신호 구간도 7.4 등급을 매겨 착수 순위에 **종류 '비고'** 로 올리고, 같은 등급 안에서 수기·변환 행 뒤에 둔다. 같은 (공급, 수요) 쌍에 수기 행이 있으면 비고 행은 만들지 않는다 (Leo 결정 2026-09-24, 골든 I3).
- '숨은변환 의심' 건도 자동화 후보이므로 보고서에서 '변환 구간'으로 함께 보여준다.

### 7.4 착수 등급 (CQ03)
- `automatable(u)` = `u.operation_mode ∈ {CLI 지원, GUI+CLI}` **또는** `u.automation_if`가 비어 있지 않고 빈 값 토큰(`rules.yaml empty_tokens` — NA·-·해당없음 포함)이 아니며
  `{없음, 모름}`에 속하지 않음 (값은 config). 한 정의 `Normalizer.automatable` 을 3D 지도(graph_view3d)·MCP(onto_store)·M4 가 쓰고, 참조 계산(oracle)은 독립 구현 (I16 개정, 2026-10-12).
- ~~공급·수요 어느 한쪽이라도 `airgap_ok = 불가`면 등급 `제외`~~ → **폐지 (Leo 2026-09-29)**: 대부분의 툴이 폐쇄망에서 구동되므로 폐쇄망 값으로 제외하지 않는다
  (양식 v1.1 에는 열도 없다). M4 에서 `airgap_excluded: []` 와 골든 재등급(P12·GRADE-SUPPLIER-X)으로 반영 — CLAUDE.md 미확정 사항.
  폐지 커밋의 범위(docs/11 7장·Q5 권장 그대로, 2026-10-02): rules·oracle·골든 2사례·테스트뿐 아니라 **스키마의 HandoffGrade `제외` 값(schema:699, 폐지 주석으로 두되 M4 v0.4 범프 때 정리)·
  등급 설명 "폐쇄망 구동으로 정한다"(schema:83)·생성물(OWL·SHACL·schema_model·문서) 재생성**까지 한 커밋에.
- 등급: 양쪽 automatable → **A**, 한쪽만 → **B**, 둘 다 아님 → **C**
- **'모름' 과 '없음' (Leo 결정 Q4, 2026-10-02 — docs/11 8장)**: 등급은 둘 다 automatable=false 로 **같다**. 대신 보고서 시트 2 에 (a) 공급·수요 양쪽의
  조작 방식·자동화 IF **원문 열**, (b) 양쪽 모두 '모름'/빈칸인 쪽에 **'미확인' 표시 열**을 둔다(등급·정렬은 A·B·C 그대로; 스키마 슬롯·enum 추가·SHACL 심각도 변경 없음).
  (c) 규칙 4열의 '모름' 을 수정 요청표에 '확인 요청' 으로 실을지는 diag 의 '모름' 비율을 본 뒤.
  **'NA'·'-' 등 빈 값 토큰은 자동화 불가로** 센다 — 반영됨 (2026-10-12, 위 첫 글머리: oracle·지도·MCP 가 같은 규칙; docs/11 6장 지적). M4 에서 자동화IF 가 'NA' 인
  툴사용이 C 로 떨어지는 골든 사례 1건을 넣는다 (합성 행 추가 → aggregates 변경, 계획된 변경). 보고서 '미확인' 표시에서 'NA' 는 '없음' 쪽 (미확인 아님).
- 정렬(가중 점수 대신 설명 가능한 순차 정렬): 등급 → 수요 측 사용 빈도 → 수요 측 사용 인원수 → 수요 측 우선순위 의견 → 공급 측 같은 순서
  → **개정 (Leo 결정 Q1, 2026-10-02 — docs/11 8장)**: 범용 확장자만 겹치고 연계 SW 도 없는 추정 수기 구간은 **같은 등급 안에서 뒤로** —
  정렬 키 = **등급 → 종류(수기·변환·비고) → 신고 여부 → 신뢰도 → 빈도 → 인원** (이어서 우선순위 의견·공급 측 같은 순서). I18 개정·oracle 동반, M4.
  Handoff 는 여러 Feed 를 묶으므로 집계 슬롯 **`declared`**(근거 Feed 중 하나라도 신고 일치)·**`confidence`**(근거 Feed 중 최고)를 두고(스키마 v0.4, M4 D1 과 한 판),
  보고서 시트 2 에 그 두 열을 보인다. 착수 순위에서 제외하지는 않는다(7.1 '범용 확장자를 제외하지 않는다' 유지). 데이터명 유사도로 신뢰도 승격은 보류.
- **변환 구간(숨은변환 의심)** 은 공급 측이 툴사용이 아니라 신고된 상대 Tool 이다 (Feed 없음). 상대 Tool 의 툴사용 각각과 쌍으로 펼쳐 위 규칙을 그대로 적용한다 (D1-2) — 행이 늘어나는 대신 행마다 근거가 추적된다.

### 7.5 고립 (CQ05), 허브 (CQ08), 분야 매트릭스 (CQ07), 영향 범위 (CQ06)
- 고립: ① 입출력 미기재 = IOSpec이 0개인 툴사용 (조사 미완) ② 무연결 = IOSpec은 있으나 Feed도 해석된 신고 상대도 없음 (독립형이거나 표기·포맷 불일치)
- 허브: 툴사용·툴별 Feed로 이어진 상대 수 상위 N. **보고만 하고 착수 순위에는 쓰지 않는다.**
- **결정 (Leo 2026-09-30) — 아래 제안을 이렇게 바꿔 확정**: ① 단위는 툴 합산이 아니라 **툴사용(파트 × 툴)** — "Excel·PPT·Word 는 모든 파트가
  쓰지만 용도가 다르다". 같은 툴을 쓰는 다른 파트 수는 참고 열로. ② 정렬 = **연결 상대 수(툴사용 기준 = I7, Feed 로 이어진 서로 다른 상대 툴사용 수, oracle `usage_partners`) → 걸린 수기·비고 구간 수 → 자동화 가능 →
  닿는 파트 수 → 빈도 → 인원** ("연결이 많을수록 에이전트 효과가 크다, 데이터 이동은 대부분 수동"). ③ 연결 수는 두 열 — 계산한 Feed 전체 /
  **신고된 것만 = `Feed.declared`** (어느 한쪽이 상대를 연계 Tool명으로 적음, 7.2 — 양쪽 상호 신고로 좁히지 않는다; Leo 결정 Q6 권장 그대로 2026-10-02, docs/11 8장) (범용 확장자 우연 일치 대비), 정렬은 전체 기준.
  저장 자리는 derived 의 파생 클래스 `ToolCandidate` + ToolUsage 파생 슬롯 `automatable`(docs/11 3장 7번, 스키마 v0.4 — M4). **v10 뷰어의 '연결 상대' 는 survey 의 신고(다른 파트의 신고까지) 를 센 잠정 과대 집계**라
  M4 보고서에 그 차이를 한 줄로 설명한다. 이하 제안 원문은 기록으로 둔다.
- **(제안 2026-09-29 — 위 결정으로 대체) 툴 기준 에이전트 후보**: Leo 요청 "수기 전달 말고도 연결이 많은 툴 위주로 선정할 수 있게". 허브를 참고용에서
  **두 번째 선정 기준**으로 올린다. 7.4 의 수기 구간 착수 순위는 그대로 두고(허브 값은 거기 섞지 않는다 — 골든 P7 사례 유지) 별도 목록을 만든다.
  - 뜻: 한 툴을 에이전트가 다룰 수 있게 감싸면(MCP 툴화) 그 툴에 걸린 연결 전부에 쓸 수 있다 — 구간 하나를 잇는 것과 다른 종류의 후보.
  - 단위 = **툴** (모든 분야의 툴사용 합산, 상세에 분야별 내역). 열 = 자동화 가능(툴사용 중 하나라도) · 쓰는 분야 · 연결 상대 툴 수(I7) · 연결 건수 ·
    닿는 분야 수(쓰는 분야 ∪ 상대 분야) · 걸린 수기·비고 구간 수와 등급 · 최대 사용 빈도 · 사용 인원 합.
  - 정렬(가중 점수 없음): 자동화 가능 → 연결 상대 툴 수 → 걸린 수기·비고 구간 수 → 닿는 분야 수 → 빈도 → 인원 → 이름. 엑셀에서 다른 열로 다시 정렬해도 된다.
  - 범용 확장자(xlsx·csv 등)로만 이어진 미신고 연결이 허브를 부풀릴 수 있다 → '연계 툴로 신고된 연결만' 센 상대 수 열을 따로 둔다 (합성 데이터는 71건 중 70건이 신고라 차이 없음).
  - 보고서 시트 7 '허브(참고)' → '툴기준_후보', 지도에 '연결 수로 크기' 와 '툴 기준 후보' 패널 (시안 `scripts/preview_map3d.py`). 골든에 툴 순위 기대값 추가.
- 분야 매트릭스: 행=공급 분야, 열=수요 분야, 값=Feed 수. 전체용과 수기용 두 장.
- 영향 범위: 주어진 (분류, 확장자)를 소비하는 툴사용에서 시작해 `eg:feeds+`로 도달하는 하류 전체.

## 8. 그래프 구성

| named graph | 내용 | 갱신 |
|---|---|---|
| `http://en-genius.local/graph/schema` | LinkML에서 생성한 OWL | 스키마 버전이 바뀔 때 |
| `http://en-genius.local/graph/survey` | 적재된 조사 인스턴스 + SurveyLoad | 적재 때마다 통째 교체 |
| `http://en-genius.local/graph/derived` | Feed, 대조 결과(`Reconciliation`)·고립 결과(`IsolationFinding`)·착수 구간(`Handoff`), `eg:feeds` — 파생 3종은 스키마 v0.2 (D1, §14) | 도출 때마다 통째 재계산 |

- 파생 노드에는 `rule_version`, `derived_from`(LOAD ID), 생성일시를 단다 (provenance).
- Fuseki: TDB2 데이터셋 `engenius`, `unionDefaultGraph true`. 올리기는 SPARQL Graph Store Protocol로 named graph 단위 PUT(교체).
  `push` 는 실행 폴더에 `derived.ttl` 이 없으면 Fuseki 의 derived 그래프를 **비운다** (재적재 뒤 옛 파생 그래프가 union 에 섞여 질의에 나오지 않도록 — docs/11 7장, M3.1 2차에서 구현).
- 로컬: rdflib Dataset에 같은 named graph로 올리고 기본 그래프를 합집합으로 설정해 Fuseki와 같은 결과가 나오게 한다.
- **적재 라운드 간 비교**(1차 적재 → 수정 요청 → 2차 적재의 이전 실행 대비 증감) 는 **M4 diag 확장 항목** — 지금 diag 는 실행 폴더 하나만 읽고 Fuseki 는 PUT 교체라 이전 판이 남지 않는다 (docs/11 7장).

**`manual` named graph 메모 (GUI 선행 제약, docs/11 3장 14번 — 코드 변경 0, 설계는 M4 뒤 GUI 때)**
- 사람이 넣는 지식(조사 엑셀 밖)은 별도 named graph `http://en-genius.local/graph/manual` 에 쌓는다. 보관 위치는 `output/` 밖·git 제외(예: `data/real/manual/`),
  `push` 는 manual 그래프를 **교체하지 않는다**(survey·derived 만). 도출은 survey ∪ manual 로 재계산. 저장 전 SHACL 검증, provenance 는 일시·사유만(인명 저장 금지, 규칙 5).
- 사람이 만든 툴·툴사용 ID 는 survey 레지스트리의 `retire_unseen` 대상이 되면 안 된다 — 별도 접두 또는 origin 표시(방식은 GUI 설계 때). 지금 레지스트리에는 origin 열이 없어
  GUI 가 공용 레지스트리로 ID 를 발급하면 다음 완전 적재가 그 ID 를 '폐기' 로 바꾼다. '고치기' 는 manual 그래프 자체를 SPARQL 1.1 Update 로 바꾸는 것이고(RDF 는 단조라 survey 값은 추가만으로 못 고친다),
  survey 값 교정은 기존 경로(D4·value_aliases·tool_aliases·수정 요청표 → 재제출) — override 층은 두지 않는다. manual 의 사람 트리플은 IO·FEED IRI(내용 해시, 라운드마다 바뀜)가 아니라
  레지스트리로 고정된 툴사용(USE) 쌍 + 분류에 앵커한다. 읽기 전용 serve 는 제안하지 않는다(.bat 가 덮음); ThreadingHTTPServer·백그라운드 스레드는 구현 메모로만.

## 9. 설정 파일 (`config/`)

| 파일 | 내용 |
|---|---|
| `header_map.yaml` | 시트별 슬롯 ← **추가** 헤더 문구 (기본 문구는 스키마 form_header 주석 — §14). 사내 문구는 오버레이 `data/real/config/header_map.yaml` 에 더한다 (시트·슬롯별 합집합, 시트 키는 v1.1 이름도; 문의처 등 제외 열 문구는 설정 오류 — 5장 1, I30) |
| `template_examples.yaml` | 템플릿 예시 행의 핵심 값 (원본 양식에서 추출) — 사내 양식판의 예시는 오버레이 `data/real/config/template_examples.yaml` 에 더한다 (시트별 합집합, `template-examples --overlay`) |
| `rules.yaml` | 방향 값, 수기 전달 값, 비고 키워드, 자동화 판정 값, 폐쇄망 제외 값, 범용 확장자, 빈도·우선순위 순위, 허브 N, 유사도 임계값, 규칙 버전, 예시 유사 문턱 `loader.example_near_ratio`(0.8)·`example_near_min_cols`(5), 만료 시기 칸 `loader.month_slots`·빈칸으로 보는 말 `loader.month_blank_values`(영구), 아는 양식 밖 시트 `loader.other_sheets`(작성안내) |
| `extensions.yaml` | 확장자 별칭(한글·영문 표기), 사내 표기 토큰, 구분자, 확장자 패턴, 비확장자 토큰, 묶음(다중 점) 확장자 — 빈 값 토큰은 `rules.yaml` `empty_tokens` |
| `tool_aliases.yaml` | 대표 툴 이름 ← 변형 표기 (검토 판정 누적) |
| `fuseki.yaml` | 엔드포인트, 데이터셋 이름, 그래프 IRI |

`rules.yaml` 예시:

```yaml

manual_transfer_values: ["메일·수기 전달"]
manual_note_keywords: ["수기", "수작업", "손으로", "복사", "재입력"]
automatable:
  operation_modes: ["CLI 지원", "GUI+CLI"]
  non_automation_if: ["없음", "모름"]       # 빈 값 토큰(empty_tokens — NA·- 등)도 자동화 불가 (7.4, I16)
airgap_excluded: ["불가"]
generic_extensions: [xlsx, xls, csv, txt, pdf, docx, pptx, hwp]
frequency_rank: {"매일": 4, "주 1회 이상": 3, "월 1회 이상": 2, "분기 이하": 1}
priority_rank: {"상": 3, "중": 2, "하": 1}
hub_top_n: 10

```

## 11. 에이전트 단계 대비 (M6, 지금은 구현하지 않음)

- MCP 서버 `ontology-query`는 **읽기 전용 질의 함수만** 노출한다: `get_usage`, `upstream`, `downstream`, `chain(max_depth)`, `manual_handoffs(field, grade)`, `impact(category, extension)`, `field_matrix`. 내부는 CQ의 템플릿 SPARQL이며 입력값을 검증한다. 자유 SPARQL은 노출하지 않는다.
- `IOSpec.security_grade`는 지금은 속성으로만 적재한다. 등급별 접근 통제는 M6 이후 MCP 게이트웨이에서 한다.
- 툴을 MCP 함수로 감쌀 때 입력·출력 정의는 해당 툴사용의 IOSpec 행에서 가져온다 (조사표 = 함수 시그니처).

## 12. 스키마 v0.1 구현 반영 (M1, 2026-09-24)

M1 에서 스키마를 만들며 이 문서와 달라지거나 구체화된 점. 근거와 검토 기록은 `docs/05_스키마_v0.1_검토.md`.

- **클래스 이름** — `Field` 는 생성되는 Pydantic 코드에서 `pydantic.Field` 를 덮어써 모든 클래스가 깨진다(실측). 스키마·파이썬 이름만 `ResearchField` 로 하고 RDF 클래스 IRI 는 `eg:Field` 그대로다 (`class_uri`).
- **SurveyLoad = 원천 파일 1개** — 분야별로 파일이 따로 올 가능성이 커서 파일마다 1건, ID `LOAD-<yyyymmddThhmmss>-<nn>`, 같은 실행은 `run_id` 로 묶는다. 실행 전체 합계·교차 파일 경고는 10장 `run_log.json` 이 담는다.
- **식별자는 노드 IRI 자체** — `eg:id` 트리플은 없다. ID 규칙(4장 형식)은 SHACL 노드 모양이 IRI 패턴으로 검사한다.
- **이름과 선택지의 리터럴 규약** — 이름 속성(rdfs:label·skos:prefLabel·skos:altLabel)만 `@ko` 를 단다. 선택지 값은 언어 태그 없는 문자열이다 (SHACL `sh:in`·OWL `owl:oneOf` 와 같은 표현).
- **3장 표에 없던 슬롯 추가** — 레지스트리 노드 `status`(활성/통합됨/폐기, 기본 활성), `Tool.merged_into`, `Field.succeeded_by` (docs/01 원칙 9); 툴 통합 다수값 계산용 `ToolUsage.reported_vendor`·`reported_kind` (양식 D·E 열은 여기로 적재하고 Tool.vendor·kind 는 다수값); 정수 변환 실패 원문 `user_count_raw`·`license_count_raw` (3장); 추적용 `source_row`·`loaded_in`; 고아 입출력 보존용 `IOSpec.owner_source_key` (io_owner 는 없을 수 있음); CQ09 용 `IOSpec.partner_unresolved` (정규화 키로 저장).
- **SHACL 검증 범위** — survey ∪ derived 합집합에 대해 돌린다 (derived 만 돌리면 Feed 가 가리키는 노드의 rdf:type 이 없어 위반). schema 그래프(OWL)는 넣지 않는다. 엔진은 Fuseki 배포본 jar 의 Jena SHACL (`engenius_onto.shacl_check`).
- **미결** — 8장 '대조·고립 결과' 저장 방식과 변환 구간 등급 위치, IO 해시 키 충돌 정책 등은 `docs/05` 의 미결 사항에서 M3·M4 전에 정한다.

## 14. 스키마 v0.2·적재기 구현 반영 (M3, 2026-09-24)

근거와 검증 기록은 `docs/07_적재_M3.md`.

- **파생 클래스 3종** — `Reconciliation`(입출력·상대 툴·판정), `IsolationFinding`(툴사용·유형), `Handoff`(착수 구간: 공급·수요 툴사용,

- **헤더 매핑의 정본은 스키마** — 적재기는 스키마 form_header 주석을 기본 문구로 쓰고, `config/header_map.yaml` 은 사내 양식 변형용
  추가 문구만 담는다 (9장 표의 '전체 매핑' 에서 바꿈 — 매핑이 두 곳이면 M1 양식 매핑 검사와 적재기가 어긋날 수 있다).
