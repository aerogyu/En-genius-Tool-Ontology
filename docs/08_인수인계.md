작업 방식
- 여러 줄 편집 스크립트·생성기는 **Write 도구로 파일을 만들어 실행**한다. bash heredoc 안의 파이썬은 `\n`·따옴표가 붕괴한다
  (이 세션에서도 cli.py 에 `"\n"` 이 실제 개행으로 들어간 사고). 한 줄 치환은 Edit 도구.
- 파일은 LF 로 쓴다 (`newline="\n"`, `.gitattributes` 가 LF 기본·xlsx binary·bat crlf).
- `git diff --check` 는 `schema/generated/` 를 빼고 돌린다 (gen-doc 이 줄 끝 공백을 만든다 — 손대지 않는 생성물).
- Python 3.10: f-string 안에서 같은 따옴표 중첩 불가. 문자열 안 `\f` 는 폼피드 (`scripts\\fuseki_start.bat`).

LinkML·스키마
- 스키마를 고치면 `python -m engenius_onto schema` (생성물 드리프트는 `--check` 와 테스트가 잡는다).
- 클래스 이름 `Field` 금지 (pydantic.Field 를 덮어씀 → `ResearchField`, RDF 는 `eg:Field`).
- OwlSchemaGenerator 파이썬 API 기본값이 CLI 와 반대 — schema_gen 이 명시한다. identifier 슬롯은 eg:id 로 나와 OWL 충족 불가·SHACL
  무효가 되므로 후처리로 지운다. HermiT 는 xsd:pattern 의 `\d`·끝 `-`·앵커를 거부.
- YAML flow 매핑 `{description: ...}` 안에 쉼표가 있으면 따옴표 (LinkML 이 `PermissibleValue.__init__() got an unexpected keyword` 로 죽는다).
- 새 열거형을 추가하면 `tests/test_schema.py` 의 열거형 수·핵심 클래스·ObjectProperty 목록을 같이 고친다.

RDF·도구
- SHACL 은 Fuseki jar 의 Jena (`shacl_check`) — Windows 절대경로를 IRI 로 못 받아 임시 폴더 상대경로로 넘긴다. 검증 범위는
  survey ∪ derived (derived 만 돌리면 sh:class 위반).
- rdflib `Graph.value(None, p)` 는 None 을 돌려준다 — 직접 순회. `Dataset(default_union=True)` 의 DeprecationWarning 은 무해.
- openpyxl read_only 워크시트는 열 순회가 없다 — 행을 zip. NFKC 가 'ㆍ'(U+318D) 를 U+119E 로 바꾼다 — 구분자에 둘 다.
- 라이선스: linkml 이 rfc3987(GPLv3+) 을 끌고 온다 — 설치 후 `pip uninstall rfc3987`. `licenses` 명령·테스트가 감시.

적재기·설정 (2차 1묶음, 2026-10-02)
- **사내 설정 오버레이** `data/real/config/<이름>.yaml` (git 제외) — `load --data real` 이 자동으로 읽는다. 합성·`--input` 적재는 `--overlay DIR` 로 지정, `--no-overlay` 로 끈다.
  합치는 법이 파일마다 다르다: `tool_aliases` 는 `aliases`·`distinct`·`merge_pairs` 합집합, `value_aliases` 는 열별 병합, `rules` 는 키 단위. 형식 오류·값 없는 키는 적재 시작 전
  `[NG] 설정 오류: <파일> <키>: …` 한 줄로 멈춘다 (ValueError → cli). 테스트에서 오버레이를 안 쓰려고 하면 `--no-overlay` 를 꼭 — `data/real/config` 가 있으면 조용히 읽힌다.
  **4차 수리 (2026-10-02)**: YAML 문법 오류도 `[NG] 설정 오류: <파일> <행>행 <열>열: YAML 문법 오류` 한 줄(값 없음, yaml 의 traceback 을 밖으로 내지 않는다) · apply-review 대상 파일(검토표·tool_aliases) 형식 오류도 한 줄 ·
  `--no-overlay` 와 `--overlay DIR` 동시 지정은 거부 · 저장소 밖 오버레이 폴더는 load_log 에 절대 경로(상대 경로로 바꾸면 저장소 밖을 가리키므로).
  **제조사 접두 흡수는 '별개 쌍이 든 그룹'·'기존 툴(활성 레지스트리) 둘 이상인 그룹'을 자동 통합하지 않는다** — 경고 + 검토표 후보로만(HITL). 테스트에서 흡수를 기대할 때 레지스트리에 활성 행이 양쪽에 있으면 안 합쳐지니 주의.
- **`tool_aliases.yaml` 의 정본은 `merge_pairs`** (`[[A 키, B 키], …]` 판정 이력, A 생존). `merge_keys` 는 apply-review 가 저장 때마다 재계산하는 파생 — 적재기도 `merge_pairs` 가 있으면
  그것으로 계산하고 파일의 `merge_keys` 와 다르면 `손으로 고친 merge_pairs` 경고. `merge_keys` 만 있는 옛 파일은 자동 승격. '별개' 는 **직접 쌍만** 되돌리고 간접 사슬은 ValueError 로
  고칠 파일을 알려 준다. 라벨(`labels`)은 판정 당시 키에 머물고 그룹 대표 이름은 적재기가 고른다 — 라벨을 따라 키를 옮기지 않는다 (#2 (a)(c) 의 ID 변동 원인).
- **apply-review 가 쓰는 곳**: 검토표가 나온 실행이 실데이터면 `data/real/config/tool_aliases.yaml` (저장소 `config/` 가 아니다). `--config-dir` 로 강제. 공개 별칭 사슬 검사는
  그곳이면 자동, 다른 폴더는 `--with-public-aliases` 플래그 (load 의 `--overlay DIR` 과 뜻이 다르다 — 폴더가 아니라 '공개 별칭을 섞어라'. 옛 이름 `--overlay` 는 apply-review 에서 오류).
- **제조사 접두 흡수(Q3(a))**: 레지스트리 활성 행이 한쪽에만 있으면 그 키를 생존 키로 — 그래야 TOOL ID 가 안 바뀐다. `rules.yaml generic_tool_names` 의 범용 이름(자체개발·매크로 등)은
  행별 `미상:<파트>/<Tool ID>` 툴이 되고, **범용 제조사는 접두로 쓰지 않는다**(Q3(b)). 새 rules 키 `tool_token_map`(C++→cpp)·`candidate_min_contain_len`(3).
- **재적재 1회성 변화 (정상)**: 연도 토큰·토큰 치환·범용 제조사 접두 제외로 키가 바뀐 툴은 TOOL ID 재발급·옛 행 폐기, 범용 이름 행이 있으면 툴 수 증가, 입출력 없는 툴사용마다
  수정 요청표에 '입출력 없음'(확인 요청) 행 추가. 사내에서 "툴 수가 늘었다/ID 가 바뀌었다" 고 오면 먼저 이걸 의심한다. 수정 요청표의 '확인 요청' 행을 담당자에게 보낼지는 Leo 결정.
- **설치 판 표식** `offline/installed_commit.txt` (1행 전체 해시, 2행 번호; 업데이트 스크립트가 쓴다, BOM·앞 7자만 있어도 읽힌다) — `diag`·`doctor` 에 7자 표시. 개발 PC 에서는 git 이 대신한다
  (`doctor` 의 `(git)`). `selftest.bat` 이 이 1행으로 `offline/selftest_<커밋>.txt` 이름을 짓는다 — 없으면 `unknown`.
- **업데이트 적용 규칙** (`scripts/build_update.py`): 사이 판 내용(KNOWN sha 집합)이면 덮어쓰고, 진짜 로컬 수정은 `<파일>.new` 로 보존(+`[주의]`), 기존 `.new` 와 다르면 `.new.<일시>`;
  백업 폴더에 `MANIFEST.txt`(A/M/D/K); 중간 누락·역행은 `y/N`. 그래서 역순으로 만든 업데이트도 적용되지만 **삭제 파일이 있는 구간은 아니다**.
- `push` 는 그 실행에 `derived.ttl` 이 없으면 Fuseki derived 그래프를 **비운다** (#25a) — 옛 도출 결과가 survey 와 어긋난 채 남지 않게. 뷰어 v11 은 활성 툴만 그리고
  `(통합·폐기 N 제외)` 로 수를 적으며, 적재가 쓴 오버레이 rules 로 판정하면 '설정 오버레이 적용' 을 표시한다 (load_log.json `config_overlay.dir`).

적재기·설정 (2차 잔여, 2026-10-12)
- **오버레이의 목록 키는 통째로 바뀐다** (사전 키는 키별 병합). 예: 사내 `rules.yaml` 에 `loader.other_sheets` 를 적으면 저장소 값(`[작성안내]`)까지 다시 적어야 하고,
  `extensions.yaml` 의 `non_extension_tokens`·`compound_extensions` 도 같다. 새 rules 키의 코드 기본값은 배포 값과 같게 둔다 — 업데이트가 rules.yaml 을 `.new` 로 남겨도 동작이 같도록(450beeb).
- **동시 적재 잠금** `<레지스트리>/.load.lock` (O_CREAT|O_EXCL): 강제 종료로 남으면 **사람이 지운다** (자동 해제 없음 — 안내 문구가 경로를 알려 준다). 테스트·리허설에서
  레지스트리를 복사할 때는 `registry.copy_registry`(잠금·임시 파일 제외)를 쓴다 — 그냥 복사하면 남은 잠금 때문에 selftest·pytest 게이트가 대량 실패한다.
- **Windows 에서 `os.kill(pid, 0)` 은 살아 있는지 확인이 아니라 그 프로세스를 끝낸다** — 잠금 소유 확인에 쓰지 않는다.
- 인명 가림 헬퍼는 `Normalizer.looks_person` · `Loader._q` · `PERSON_MASK` 하나로 모았다 — 새 경고·수정 요청표·검토표 표기 칸에 원문을 인용하면 반드시 경유. oracle 은 가림을 흉내 내지 않는다(합성에 인명 유사 값 없음).
- 엑셀 '캐시 없는 수식' 판별은 openpyxl 이 아니라 시트 XML 직접(`loader.formula_cells_without_cache`) — openpyxl 은 `<v></v>`(엑셀이 저장한 빈 문자열 수식)와 `<v>` 없음을 구별 못 한다.
- 일반 모드 워크시트를 `iter_rows` 로 훑으면 먼 서식 칸 하나에 `max_row×max_column` 직사각형 전체가 만들어진다(수 GB) — 실제 칸(`ws._cells`)만 훑는다 (docs/09 C7 해소).
- bash heredoc 안 파이썬 문자열의 `\r`·`\t` 가 실제 CR·TAB 이 되어 README 의 `data\real\config` 경로가 깨진 일이 또 있었다 — 역슬래시가 든 문서는 Edit/Write 로만.
