# 12. 사내 AI 플랫폼 — Tool Ontology MCP 서버 등록 문의 (초안, 2026-10-08)

Leo 가 플랫폼 개발자에게 보낼 문의 초안. 답을 받으면 이 문서 4장에 적고, M6(온톨로지 MCP 서버) 설계의 입력으로 쓴다.
사내 IP·호스트명은 이 저장소에 적지 않는다 (문의 본문에서는 "플랫폼 서버" 로 부른다).

---

## 1. 배경 (우리가 가진 것)

- **Tool Ontology**: 연구소 각 파트의 툴 조사(21 파트, 툴 180여 개, 툴사용 280여 건, 입출력 320여 건)를 지식 그래프(RDF)로 적재한 것.
  "어느 툴이 어느 툴에 무엇을 넘기는가", "사람 손으로 옮기는 구간은 어디인가", "어느 툴이 허브인가" 를 질의할 수 있다.
- 저장 형태: **Apache Jena Fuseki**(그래프 DB, 표준 SPARQL) 또는 **TTL 파일**. 지금은 담당자(Leo) PC 에 있고, 데이터 갱신(조사 엑셀 → 그래프)도 그 PC 에서 한다.
- 제공하려는 것: **MCP 서버 하나** — 읽기 전용 도구 6~7개 (툴 찾기 · 툴의 연결 상대 · 파트가 쓰는 툴 · 수기 전달 구간 착수 순위 · 툴 기준 에이전트 후보 · 데이터 전달 경로 · 제한된 SPARQL 읽기).
  쓰기 도구는 없다(판정은 엔지니어가 한다). 그래프에 인명은 없다. 공식 MCP Python SDK(MIT)로 만들며 외부 네트워크 호출은 없다.
- 데이터는 **공유 자산**이라 CATIA 처럼 "각자 PC 의 도구" 가 아니라 **논문 검색(RAG)처럼 한 곳에서 도는 도구**로 붙이고 싶다. 사용자 PC 에는 아무것도 설치하지 않는 것이 목표.

## 2. 문의 (보낼 본문)

> 안녕하세요. Tool Ontology(툴 간 데이터 연결 지식 그래프)를 플랫폼 에이전트의 **도구**로 제공하려고 합니다.
> 읽기 전용 MCP 서버 하나(도구 6~7개, 공식 MCP Python SDK)를 준비 중인데, 플랫폼에 어떻게 등록하면 되는지 아래를 확인 부탁드립니다.
>
> **A. 등록 방식**
> 1. 플랫폼에 **원격 MCP 서버를 URL 로 등록**할 수 있나요? (Streamable HTTP 또는 SSE 전송 — 저희가 한 곳에 띄워 두고 주소만 드리는 형태)
>    - 가능하면: 등록 화면/설정 파일 형식, 서버 이름·설명·도구 목록은 자동으로 읽히는지(tools/list), 등록에 관리자 권한이 필요한지
> 2. URL 등록이 안 되면: 지금 **En-genius MCP(로컬 브리지)에 묶여 있는 서버들(Office·CATIA 등)은 어떤 형식으로 들어가 있나요?**
>    (stdio 로 띄우는 파이썬/exe 인지, 설정 파일 — 예: `mcpServers` JSON — 에 command/args 를 적는 방식인지) 저희 서버를 같은 방식으로 넣으려면 무엇을 드리면 되는지
> 3. **논문 검색(RAG)** 처럼 서버 쪽에서 도는 도구는 어떻게 등록돼 있나요? 저희 도구도 그 자리에 넣을 수 있는지 (사용자 PC 설치 없이 모두가 쓰는 것이 목표입니다)
>
> **B. 네트워크·배치**
> 4. 저희 서버를 **처음에는 제 PC** 에 띄우려 합니다. 플랫폼 서버(또는 각 사용자의 En-genius MCP)가 **제 PC 의 포트로 접속**하는 구조가 되나요, 아니면 반대로 제 쪽에서 플랫폼에 접속(아웃바운드)하는 구조인가요?
>    방화벽 예외·고정 IP·포트 지정 규칙이 있으면 알려 주세요.
> 5. 나중에 **플랫폼 서버에 같이 올릴 수** 있나요? (파이썬 3.10 프로세스 1개 + 그래프 DB(Fuseki, Java 21) 또는 TTL 파일 2개. 메모리 수백 MB 수준)
>    올릴 수 있다면 배포 형식(폴더 복사 / 컨테이너 / 서비스 등록)과 담당자를 알려 주세요.
>
> **C. 인증·보안**
> 6. MCP 서버 호출에 **인증**(토큰·API 키·헤더)이 필요한가요? 필요하면 발급 절차와 헤더 형식
> 7. 도구 호출 **로그**는 플랫폼에 남나요? (누가 어떤 질의를 했는지 — 저희 쪽에서도 남길지 정하려고 합니다)
> 8. 사용자별 **도구 사용 권한** 설정이 있나요? (특정 에이전트/부서만 쓰게)
>
> **D. 도구 규격·제한**
> 9. 도구 **입출력 형식**에 제한이 있나요? (JSON Schema 입력, 텍스트/JSON 출력, 한 번에 반환 가능한 크기 — 표 수백 행을 돌려줄 때)
> 10. 한 서버의 **도구 개수 상한**, 도구 이름 규칙(영문만? 길이?), 설명 길이 제한
> 11. 에이전트가 **같은 도구를 여러 번 연속 호출**(예: 툴 찾기 → 연결 상대 → 착수 순위)하는 것을 허용하나요? 호출 횟수·시간 제한이 있으면 값
> 12. 플랫폼이 쓰는 **MCP 프로토콜 버전**(spec 날짜) 또는 클라이언트 라이브러리 이름·버전 — 저희 SDK 버전을 맞추려 합니다
>
> **E. 운영**
> 13. 저희 서버가 꺼져 있을 때 플랫폼 쪽 동작(오류 표시 / 에이전트 생성 불가 등)
> 14. 서버를 **업데이트**(도구 추가·데이터 갱신)할 때 재등록이 필요한지, 플랫폼 재시작이 필요한지
> 15. 테스트용으로 먼저 붙여 볼 수 있는 **개발/샌드박스 환경**이 있는지
>
> 참고로 저희 서버는 읽기 전용이고 외부 네트워크를 쓰지 않으며, 그래프에 인명·연락처는 들어 있지 않습니다. 필요한 패키지는 전부 MIT/BSD/Apache 계열입니다.
> 답변 주시면 그에 맞춰 서버 형식(전송 방식·실행 방법)을 정해 테스트 요청드리겠습니다. 감사합니다.

## 3. 답에 따라 갈리는 설계 (우리 쪽 메모)

| 답 | 서버 모양 | 띄우는 곳 | 사용자 설치 |
|---|---|---|---|
| A1 가능 (URL 등록) | Streamable HTTP MCP 서버 (`mcp` SDK, uvicorn) | Leo PC → 나중에 플랫폼 서버 | 없음 |
| A2 만 가능 (로컬 브리지 묶음) | stdio 서버를 브리지 묶음에 포함 — **단 데이터는 원격**(서버 안에서 Fuseki URL 로 접속) | 브리지는 각 PC, 데이터·Fuseki 는 한 곳 | 없음 (브리지 갱신만) |
| A3 가능 (서버 쪽 도구) | 플랫폼 개발자가 정한 형식 (HTTP MCP 가 가장 가까움) | 플랫폼 서버 | 없음 |

- 어느 경우든 **Fuseki 는 한 곳**. A2 에서도 브리지 안의 우리 서버는 "DB 클라이언트" 일 뿐 데이터를 갖지 않는다.
- 데이터가 작으면 Fuseki 대신 **TTL 파일 + rdflib** 로 MCP 서버 안에서 직접 읽는 선택지도 있다 (Java 불필요). 갱신 = TTL 파일 교체.
- 인증(C6)이 있으면 설정 파일(`config/mcp.yaml`, 값은 git 밖)로 받는다. 로그(C7)는 우리 쪽에도 질의 종류·시각만 남긴다(인명·값 없음).
- 반입 패키지에 추가할 것(M6 때 docs/04): `mcp` + 전이 의존(anyio·httpx·httpx-sse·pydantic-settings·sse-starlette·starlette·uvicorn·python-multipart 등, MIT/BSD/Apache).

## 4. 받은 답 (기입란)

**2026-10-08 (문의 전 확인)**: Leo PC 에서 `netstat -ano | findstr <플랫폼 포트>` → En-genius MCP 프로세스가 플랫폼 주소로 **ESTABLISHED 2줄, LISTENING 없음**
→ **아웃바운드 확정** (브리지가 플랫폼에 먼저 접속해 유지). 따라서 1차 형태 = **브리지 묶음에 들어가는 stdio MCP 서버**, 데이터·Fuseki 는 Leo PC, 처음엔 Leo 혼자 사용.

## 5. 만든 서버 — M6 v0 (2026-10-09)

- 형태: **stdio MCP 서버** `scripts/mcp_server.py` (= `python -m engenius_onto mcp`), 공식 SDK `mcp==1.30.0` FastMCP, 읽기 전용 도구 8개 — README_offline 9장.
- 데이터: 최신 실데이터 적재의 survey.ttl 을 rdflib 로 (Fuseki 불필요, `--backend fuseki` 선택 가능). 재적재하면 다음 호출에 자동 반영.
- 질의 층 `onto_store.py` 는 3D 뷰어와 같은 정의 — 툴 기준 후보 순위가 지도와 행 단위로 같음을 테스트가 잡는다.
- 출력: 마크다운 표(텍스트) — 어느 MCP 판·클라이언트에서도 읽힌다. 모든 칸에 인명 유사 표기 가리기.
- **Windows 함정**: stdio 전송이 stdin 파이프를 다른 스레드에서 동기 읽기하는 동안 도구 스레드가 numpy 같은 C 확장을 처음 import 하면 영구 대기 →
  서버 시작 때 도구를 한 번씩 돌려 import 를 끝낸다 (`warm_up`). `tests/test_mcp_server.py` 가 브리지와 같은 실행(`python -X utf8 scripts/mcp_server.py`,
  PYTHONPATH·PYTHONUTF8 없음, 다른 작업 폴더)으로 initialize → tools/list → tools/call 을 확인한다.
- 남은 것: 플랫폼 개발자 답(브리지 설정 형식·MCP 판)에 맞춰 등록 → Leo 에이전트에서 실제 호출 확인. M4 뒤 계산 연결·착수 순위·경로 도구 추가.
