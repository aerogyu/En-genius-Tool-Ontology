# 01. 배경과 결정사항

claude.ai에서 Leo와 논의해 확정한 내용이다. 여기 적힌 결정은 **다시 논의하지 않는다.** 바꿔야 할 근거가 생기면 Leo에게 먼저 제안한다.

## 1. 배경

- **En-Genius**: 한화에어로스페이스 가스터빈 엔진 개발 AI 플랫폼. AX TF가 추진하며, DX 계층(데이터·온톨로지·PDM 연계)과 AX 계층(LLM·RAG·에이전트)으로 구성된다. Leo는 SAS(2차유로) 도메인 리드.
- **환경**: 모든 시스템은 사내 폐쇄망(방산망) 온프레미스. 클라우드 불가. LLM과 GPU는 전사에서 제공한다.
- **온톨로지 플랫폼**: 지멘스 Graph Studio 기반 PoC가 진행 중이지만 일정이 늦어지고 있고 투자심의 통과가 불확실하다. 그래서 **오픈소스 트랙(플랜 B)**을 병행한다.
- **툴 조사**: 연구소 24개 분야, 274건. 이 저장소에서 만든 조사 양식(`reference/`)을 일부 수정해 배포했다. 274는 분야별 응답 합계이므로 같은 툴이 중복돼 있을 수 있다.
- **최종 목표**: 사람이 툴을 직접 조작하지 않고, LLM에 명령하면 에이전트가 툴을 써서 일하는 구조. 첫 단계로 툴 연결 그래프를 만들어 자동화 대상을 데이터로 고른다.

## 2. 핵심 원칙

1. **온톨로지는 SW가 아니라 설계(스키마) + 데이터다.** SW는 그걸 만들고 담고 쓰는 도구다. DB에 비유하면 스키마=ERD, 저장소=DBMS, 적재=ETL, SPARQL=SQL, 에이전트=그 DB를 쓰는 앱이다.
2. **표준 준수(W3C RDF·SPARQL·OWL·SHACL).** 그래야 저장소를 바꿔 끼울 수 있고 PoC 산출물도 이식된다.
3. **연결은 툴끼리가 아니라 데이터를 통해 생긴다.** A의 출력과 B의 입력이 같은 데이터면 A→B. 판정 키는 '분류 + 확장자'다. 분류만 쓰면 너무 많이 이어지고, 자유 텍스트 명칭은 표기가 제각각이라 이어지지 않는다.
4. **계산된 연결과 신고된 연결(연계 SW명)의 대조가 첫 분석 산출물이다.** 신고는 됐는데 계산이 안 되면 누군가 중간에서 포맷을 변환하고 있다는 신호(숨은 수작업)다.
5. **에이전트 대상은 '연결 많은 툴'이 아니라 '손으로 이어진 구간'이다.** 엑셀·CATIA 같은 범용 허브 툴은 연결 수 1위가 되지만 에이전트 대상이라는 뜻은 아니다. 순위는 툴이 아니라 구간에 매긴다.
6. **에이전트는 계산하지도, 판정하지도 않는다.** 엔지니어가 검증한 실행 스크립트·입력 템플릿을 MCP 함수로 만들고, LLM은 어떤 함수를 어떤 값으로 부를지만 정한다. 에이전트가 만든 입력·결과 파일은 남겨 엔지니어가 툴에서 직접 열어볼 수 있게 하고, 판정은 엔지니어가 한다(HITL). 조사표의 입출력 행이 곧 그 함수의 입력·출력 정의다.
7. **툴 기능은 MCP 함수로 공용화한다.** 가치 큰 체인은 대개 성능 → SAS → 열해석처럼 분야 경계를 넘으므로, 분야를 넘는 작업은 툴 연결 그래프를 지도로 쓰는 조율 에이전트가 잇는다.
8. **보안(L1~L5)과 감사로그는 저장소가 아니라 MCP 게이트웨이 한 층에서 강제한다.** 그래야 저장소를 바꿔도 보안 로직이 살아남는다. 온톨로지 조회도 자유 SPARQL이 아니라 정의된 질의 함수로만 노출한다 (스키마가 행위를 한정).
9. **조직(분야)은 문자열이 아니라 노드다.** 개명은 속성 갱신, 통폐합은 승계 관계로 처리한다. 인명은 저장하지 않는다. ID는 의미 없는 일련번호, 삭제 대신 상태 전이, 스키마는 Git으로 관리한다.
10. **RAG 우선, ML 제외.** 학습 데이터가 부족해 ML 기반 접근은 범위 밖이다. 판정 계층은 결정론적 규칙과 기존 물리 솔버를 쓴다.
11. **주장은 보수적으로.** 수치는 추적 가능한 것만 쓰고, 추정은 추정이라고 표시한다.

## 3. SW 선정 (확정)

| 역할 | 선정 | 선정 이유 |
|---|---|---|
| 스키마 | LinkML | YAML 한 원본에서 OWL·SHACL·Pydantic을 생성 → 저장소·검증·LLM 구조화 추출이 같은 원본을 공유. 모든 데이터가 여기에 묶이므로 가장 비싼 결정 |
| 스키마 검토 | Protégé | LinkML이 만든 OWL을 시각적으로 확인하는 뷰어 (편집 마스터 아님) |
| 그래프 저장소 | Apache Jena Fuseki | 아파치 재단 관리로 특정 회사 사정에 휘둘리지 않음. RDF 저장소끼리는 데이터 이식이 가능해 선택 리스크가 낮음 |
| 에이전트 | LangGraph | 기존 RAG 계획(LangChain)과 같은 계열, HITL 승인 중단점 내장 |
| 툴 연결 | MCP 공식 Python SDK (+ langchain-mcp-adapters) | 툴을 MCP로 감싸 두면 에이전트 프레임워크를 바꿔도 툴은 그대로 |
| 기존 유지 | Qdrant, BGE-m3/KURE | 벡터 RAG 계층 (이 저장소 범위 밖) |

참고: Graph Studio의 원개발사 Cambridge Semantics는 2024년 Altair에 인수됐고, 그 Altair가 다시 지멘스에 인수됐다. 수십 년 가는 엔진 과제에서 벤더 교체는 현실적인 리스크다.

## 4. 검토 후 제외한 것 (재제안하지 않음)

| 대상 | 제외 이유 |
|---|---|
| Neo4j 등 비RDF 그래프 | PoC 산출물(OWL/TTL)을 변환해야 하고 표준에서 벗어남 |
| GraphDB Free | 무료지만 기능이 제한된 비오픈소스 |
| Open WebUI | 30일 사용자 50명을 넘으면 엔터프라이즈 라이선스 없이 브랜딩(En-Genius) 변경 불가 |
| Dify | 프런트엔드 로고 변경 금지, 워크스페이스 여러 개 운영(=멀티테넌트)은 별도 허가 필요 |
| 스키마 없는 자유 추출(LightRAG류)로 온톨로지 생성 | 같은 대상이 이름만 다른 노드로 쪼개지고 관계명이 임의로 생겨 그래프가 오염됨 |
| Llama 계열 LLM | 이용 정책상 군사 관련 사용 제한 — 법무 검토 필요 (LLM은 전사 제공이라 이 저장소 범위 밖) |

## 5. 나중에 고를 것 (필요 시점의 기본값)

문서 파싱 Docling, 채팅 화면 LibreChat(MIT), 승인 화면 Appsmith, 에이전트 로그 Langfuse, 검색 품질 평가 RAGAS, 설계 루프 OpenMDAO, 정형 소스 커넥터 Morph-KGC·Ontop. 모두 허용형 라이선스. 이 저장소의 M0~M5에는 필요 없다.

## 6. 지멘스 PoC와의 관계

- PoC 산출물을 OWL/TTL 표준 포맷, 표준 SPARQL 질의, (Mendix 밖) 프롬프트·도구 정의로 인수하면 이 저장소의 Fuseki에 그대로 올릴 수 있다. 이 인수 조건은 Leo가 챙긴다.
- PoC는 WBS(Lv.3~Lv.6) 기반 온톨로지를 만든다. 나중에 WBS Lv.6 업무와 툴을 '사용한다'로 이으면 "업무 단계를 인지하면 해당 툴을 호출하는" 구조의 연결고리가 된다. 이 저장소의 스키마는 그 확장을 막지 않게 설계한다.
