# 04. 반입 목록

폐쇄망 반입은 심사 비용이 크다. **새 의존성을 추가하면 반드시 이 표에 라이선스와 함께 적는다.** 허용형 라이선스(Apache·MIT·BSD 계열)만 허용한다.

| Apache Jena Fuseki | 그래프 저장소 | Apache 2.0 | zip 배포본. 설정 파일과 함께 반입 |
| Java 17 이상 | Fuseki 실행 | OpenJDK (GPLv2+CE) | 사내에 있으면 생략. Jena 5 계열 요구사항 |

> **v0.1 변경 (M0, 2026-09-24): LinkML 은 반입 대상에서 뺐다.** 전이 의존까지
> 전수 조사하니 `linkml → jsonschema[format] → rfc3987` 이 **GPLv3+** 였다 (절대 규칙 4
> 위반). LinkML 은 여전히 스키마 마스터지만 **개발 PC 에서만** 쓴다 — `gen-owl`·
> `gen-shacl`·`gen-pydantic` 생성물을 `schema/` 에 커밋하고, 사내 런타임은 생성된
> Pydantic 클래스로 검증한다 (docs/02 §5.6 이 이미 허용하는 경로). 부수 효과로 반입
> 패키지가 95개 → 17개로 줄었다. 대가: 사내에서 스키마를 고치려면 LinkML 을 별도 반입해야
> 한다 — 스키마 변경은 이 저장소에서 하고 생성물만 반입하는 흐름이 정상이다.

## 3. 개발 전용 (반입 불필요)

pytest(MIT) 등 테스트 도구는 `requirements-dev.txt`에 두고, 사내에서 테스트까지 돌릴 경우에만 반입한다.

## 4. 실행 요건

- 파이썬 **3.10 이상** (MCP SDK·LangGraph 요구)
- Java **17 이상** (Jena 5 계열 Fuseki)
- 사내 OS와 파이썬 버전: **미확정 — Leo 확인 필요** (wheel 준비에 필수)

## 5. 오프라인 설치 절차

사내 PyPI 미러(Nexus 등)가 있으면 거기 등록 요청이 가장 빠르다. 없으면:

```
# 외부 PC — 반드시 사내와 같은 OS·파이썬 버전
pip download -r requirements.lock -d offline/wheels

# 사내 — offline/wheels 폴더 반입 후
pip install --no-index --find-links offline/wheels -r requirements.lock
```

- OS·파이썬 버전이 다르면 사내에서 설치가 실패한다 (가장 흔한 사고). 같은 환경을 만들 수 없으면 `--platform`, `--python-version`, `--only-binary=:all:` 옵션으로 받고, wheel이 없는 패키지는 따로 확인한다.
- `requirements.lock`은 `==`로 버전을 고정한다. 신청서 첨부 자료이자 환경 재현 기록이다.
- 반입 전 새 가상환경에서 `--no-index` 설치를 한 번 시험한다 (M5 완료 기준).
