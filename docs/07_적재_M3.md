# 07. 적재 파이프라인 (M3)

조사 엑셀을 읽어 survey 그래프(TTL)로 만드는 단계의 기록. 설계 기준은 `docs/02` 5·6장, 규칙 세부는 골든
interpretations(I1~I37). 합성 데이터로만 개발·시험했다.

## 1. 쓰는 법

```bat
python -m engenius_onto load                 :: data/synthetic/survey → output/<실행ID>/ (사내: --data real)
python -m engenius_onto push                 :: 최신 실행의 survey.ttl + 스키마 OWL 을 Fuseki named graph 로 교체
python -m engenius_onto apply-review output\<실행ID>\tool_review.csv   :: 툴 통합 판정을 config 에 반영 ('통합 n건, 별개 m건, 통합 해제 k건 (연계 Tool명 대응 a건 · 누락 확인 b건)')
python -m engenius_onto template-examples --form <양식.xlsx>          :: 양식의 예시 행을 config 로 추출 (저장소 기본 양식 v1.0·v1.1)
python -m engenius_onto template-examples --form <양식.xlsx> --overlay :: 사내 양식판의 예시를 data/real/config 오버레이에 더함 (2026-10-12)
```

| 산출물 | 내용 |
|---|---|
| `output/<실행ID>/survey.ttl` | survey named graph — 분야·툴·분류·툴사용·입출력·적재 기록(SurveyLoad) |
| `output/<실행ID>/load_log.json` | 파일별 건수, 제외 행과 사유, 경고, 행 단위 스키마 검증, 툴 통합 후보·속성 엇갈림, 조사 누락 후보, 이번 실행의 툴 키 `tool_keys`(apply-review 가 연계 행 검사에 씀), 레지스트리 요약, SHACL 결과 |
| `output/<실행ID>/tool_review.csv` | 툴 통합 후보 검토표 (엑셀에서 열림) — '판정' 열에 통합/별개. 통합 후보 행 뒤에 사유 '연계SW 미해석' 행 (해석 못 한 연계 SW명 — docs/02 6.3, 2026-10-12). 표기 칸이 `= + - @` 로 시작하면 앞에 `'` (엑셀 수식 방지) |
| `data/<synthetic\|real>/registry/*.csv` | FLD·TOOL·USE·CAT ID 레지스트리 (제자리 갱신, 상태 열 포함). **엑셀로 열어 저장하지 않는다** — 적재가 엑셀 손상(`3-1`→`03월 01일` 등)을 검사해 설명되는 행은 되살리고 나머지는 경고 (docs/09 #15 (4)) |

SHACL 검증은 `FUSEKI_HOME`·`JAVA_HOME` 이 잡혀 있으면 자동으로 돈다 (Fuseki jar 의 Jena, 추가 반입 없음). 위반은
적재를 막지 않고 경고 보고서로 남는다 (D4).

실행 안전 (docs/09 7장, 2026-10-12):
- **동시 적재 잠금** — 적재는 레지스트리 폴더에 `.load.lock`(pid·시작 시각만)을 `O_CREAT|O_EXCL` 로 만들고 레지스트리 읽기부터 저장·산출물 쓰기까지 쥔다.
  이미 있으면 적재하지 않고 `[NG] 레지스트리 사용 중: …` 한 줄, rc 2 (`load.bat` 의 '2 stopped'). 끝나면 지운다 (예외·Ctrl+C 포함). 창을 강제로 닫아 남은 파일은
  **자동으로 풀지 않는다** — 사람이 지운다 (Windows 의 `os.kill(pid, 0)` 은 살아 있는지 보지 않고 그 프로세스를 끝내므로 pid 로 확인하지 않는다).
  `save_registry=False`(dry-run) 는 잠그지 않는다. apply-review 는 레지스트리를 쓰지 않아 잠그지 않는다. `.gitignore` 에 `.load.lock`.
- **같은 초 두 실행** — 실행 폴더 `output/<실행ID>` 가 이미 있으면 1초씩 밀어 새 폴더를 만든다 (실행 ID·적재 시각·LOAD ID 가 함께 밀린다; 형식은 그대로라
  LOAD ID 패턴 #25c 와 맞는다). 앞 실행의 산출물을 덮어쓰지 않는다. 적재가 예외로 멈추면 비어 있는 실행 폴더는 지운다.
- 한계 (C14): 일회성 전이 경고('파트 신규·폐기 동시'·'파트 약칭 개명 반영' 등)는 레지스트리 차이로 계산한다 — 레지스트리 저장 뒤 산출물 쓰기가 실패하면
  다시 돌려도 나오지 않는다.

## 3. 스키마 v0.2

- 파생 클래스 `Reconciliation`(입출력·상대 툴·판정), `IsolationFinding`(툴사용·유형) — D1 대로.

  했으나, 같이 승인된 D1-2(변환 구간을 상대 툴의 사용마다 펼침) 때문에 한 대조 결과에 등급이 여럿 생긴다 — 합성 데이터에서도
  CATIA 두 사용이 A·B 로 갈린다. 그래서 착수 순위 1행 = (공급 툴사용, 수요 툴사용, 종류: 수기·변환·비고) 에 등급·근거
  입출력·순위를 두는 클래스를 따로 뒀다. 골든 handoff_ranking 과 1:1 이고, 보고서 시트 2 와 M6 `manual_handoffs` 의 원천이다.
  Reconciliation 에는 등급을 두지 않는다.
- `grade`·`supplier`·`consumer` 를 Feed 전용 속성에서 공용 슬롯으로 올려 Feed·Handoff 가 같이 쓴다 (IRI 불변).
- `DataCategory.status` 추가 — D7 은 분류도 폐기 상태로 계속 내기로 했는데 v0.1 에 슬롯이 없었다.

## 5. 한계·다음

- 합성 파일은 openpyxl 로 만들어 실제 Excel 저장본과 다르다 (B 열 수식 캐시값, 데이터 유효성 형식). 적재기는 둘 다 쓰지 않는다 —
  실제 회신 파일 첫 적재 때 헤더 경고·예시 행 제외 건수를 먼저 본다. 2026-10-12 판부터는 '예시와 거의 같은 행'(예시를 고쳐 남긴 행 — 응답으로 적재)·
  '중복 SW ID — 예시 유사 행 제외'(같은 Tool ID 의 진짜 행으로 교체)·'예시 행 판별 설정 점검'(시트에 정확한 예시 0 — 고친 예시가 아니면 양식판 예시가
  설정과 다름 → `template-examples --overlay`) 경고와 diag 파트별 표의 '예시 유사' 열도 본다 (I15 개정, docs/09 #3).
- 같은 입출력 행에 같은 미조사 툴을 두 번 적으면 RDF 는 한 번만 남는다 (집합). 조사 누락 후보의 언급 횟수는 행 단위로 센다.
- 파일명이 규칙 밖이면 분야를 몰라 재발송 판정·담당 부서 대조를 하지 않는다 (경고). 이름은 해시로만 기록 (같은 내용 사본은 `-2`, 원래 이름 대신 load_log `files[].index`).
  규칙 밖 파일끼리·규칙 안 파일과 Tool ID 가 겹치면 경고하고 구분 키로 나눠 둘 다 적재한다 (I36) — 규칙 밖 파일의 구분 키(`@file-<sha10>`)는 내용이 바뀌면 새 USE ID (C4 의 대가).
- 다음 = M4: 도출 규칙(SPARQL CONSTRUCT)으로 Feed·Reconciliation·IsolationFinding·Handoff 를 derived 그래프에 만들고,
  골든(Feed 71·대조 103·착수 15행 등)과 대조, 보고서 10시트 + 툴 연결 지도(HTML, 오프라인). 끝나면 Leo 확인 ②.
