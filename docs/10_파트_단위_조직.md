## 1. 결론 먼저

- **개수가 달라도 된다.** 온톨로지의 조직 노드(`ResearchField`, RDF `eg:Field`, ID `FLD-nnn`)를 **응답 단위(= 담당자 1명 = 파일 1개)**로
  정의하면 그만이다. '담당 부서' 드롭다운 값(10개)은 그 단위의 **분류 속성**으로 남긴다 (묶어 보기·집계용).
- DB 비유: `parts` 테이블 23행(PK = 무의미 FLD ID, 자연키 = 약칭) + 분류 컬럼 `domain`. 조사 파일은 단위당 1개.
- 상위 스키마 v0.2 §9 가 이미 이렇게 돼 있다 — 조직은 노드, 이름은 속성, 개명은 라벨 갱신, **분할은 새 노드 + 승계(succeeded_by)**.
  CD·FEM 분할은 이 승계 엣지로 표현되므로 분할 전에 적재해도 ID 체계는 깨지지 않는다.
- 한 약칭이 여러 파트를 묶어 응답한 경우가 많다 (PL = PMO1·PMO2, IPS = 3개 파트 …). 지금은 그 묶음이 노드 하나이고, 묶인 파트 이름은
  `parts.yaml parts:` 에 적어 둔다 — 나중에 나눠 받으면 CD 와 같은 방식으로 승계한다.

## 3. 설계 (M3.1 묶음 T, 스키마 v0.3)

1. **`config/parts.yaml`**: 약칭 → 정식 이름(FLD 라벨), 묶인 파트, 허용 '담당 부서' 값, 상태, 승계(`succeeds: [CD]`). 사내에서 편집.
   FLD 노드의 라벨은 정식 이름, `skos:altLabel` 에 약칭. ID 는 지금처럼 레지스트리가 발급하는 무의미 번호.
2. **파일명**: 규칙은 그대로 `Tool조사_<약칭>_<YYYYMMDD>.xlsx` (docs/02 5-1 의 `<부서>` 자리에 약칭). ASCII 라 괄호·공백 문제가 없다.
   약칭 미정 2개는 약칭이 정해진 뒤 이름 붙인다 (급하면 임시 코드로 적재하고 #25b `field_renames.yaml` 로 개명).
3. **적재기**: FLD 키 = **파일명의 약칭** (지금은 행의 '담당 부서' 값). 행의 '담당 부서' 는 새 슬롯 `domain`(가칭)에 **원문 그대로** 저장한다.
   열거형은 드롭다운 10개 + **'기타'** — 드롭다운에는 없지만 3행 안내가 "목록에 없으면 '기타'" 라고 했으므로 경고 없이 받는다.
   parts.yaml 의 `domains` 에 없는 값이면 경고만. 보고서·연결 지도의 '부서 묶음' 은 행 값이 아니라 **parts.yaml `domains` 의 첫 값**을 쓴다 —
   그래서 Leo 가 응답의 '기타' 를 약칭으로 고쳐 쓸 필요가 없다 (이력이 남지 않는 손 편집 대신 설정으로 분류한다. 판단은 엔지니어, 데이터는 원문).
   Tool ID 접두어가 파일 약칭과 다르면(예: CDT 파일에 CD-01) 경고만 — 값은 보존.
   docs/09 #1 의 '파일 간 같은 (담당 부서, SW ID)' 충돌은 약칭이 키가 되면 구조적으로 사라진다 (#1 (A) 의 `@파일분야` 접미는 안전망으로 유지).
4. **분할(CD→CDT/CDC1/CDC2, FEM→…)**: 분할된 파일이 오면 옛 FLD 'CD' 는 status 폐기 + `succeeded_by` 새 FLD 들 (parts.yaml `succeeds`).
   분할 파일이 안 오면 CD 한 노드로 간다 — 그 파트 **사이**의 수기 구간은 안 보인다 (분할을 요청하는 이유).
5. **보고서·연결 지도(M4)**: 단위 매트릭스 23×23 이 기본, '담당 부서'(parts.yaml domains) 로 묶어 보기를 옵션으로.
   '기타' 가 10개 단위라 그 묶음은 크다 — 필요하면 parts.yaml 에서 세분한다 (예: IPS 를 체계로).
6. **골든 영향**: 합성 데이터는 지금 '파일 분야 = 담당 부서 값'(10개 체계)이다. `synthetic_parts_are_domains` 로 합성 파트(약칭 = 분야명)를 만들어
   골든 값(Feed 71·대조 103행·착수 15행)을 그대로 유지하고, v1.1 형식 합성 파일 1개는 약칭 파일명으로 추가한다.

## 3-1. 갱신 (2026-09-30, Leo)

- 형상설계(CD) → **MDT(터빈 형상설계)·MDC(압축기 형상설계, 담당자 2명)**. 둘이 **엑셀 하나**에 들어 있고 Tool ID 가 `MDT-1~9`·`MDC-1~8` 로 나뉜다
  → 파일명 약칭은 **MD** (묶음), 행의 Tool ID 앞부분으로 파트를 정한다 (`parts.yaml file_bundles`, M3.1 T). 담당 부서: MDT=터빈, MDC=압축기 (확인).
- FEM 은 **나누지 않는다** — 담당자 2명을 한 단위로 (에이전트 개발은 담당자별로 맡김).
- 연료·윤활·기어박스 = **GBLB**, 전기·전자·제어 = **CSD**. FEM = Cold Part 구조·Hot Part 구조 (Leo 가 2장 표에 기입).
- 그래서 파일 20개 · 파트(FLD) 21개. 약칭 전부 확정.

## 5. 엑셀 파일명 약속 (2026-09-30 확정)

`Tool조사_<약칭>_<YYYYMMDD>.xlsx`

| 약칭 (파일명) | 파트 (FLD) | 약칭 (파일명) | 파트 (FLD) |
|---|---|---|---|
| PL | PL | FEM | FEM |
| TEST | TEST | FS | FS |
| PRF | PRF | RE | RE |
| CMP | CMP | EC | EC |
| COMB | COMB | ACT | ACT |
| TA | TA | MAT | MAT |
| CL | CL | PE | PE |
| SAS | SAS | GBLB | GBLB |
| **MD** | **MDT + MDC** (Tool ID 로 나눔) | CSD | CSD |
| IPS | IPS | RSP | RSP |

1. 약칭은 위 표 그대로 영문 대문자. 구분자는 `_` 두 개뿐 (공백 금지).
2. 날짜 = 파일을 **받은 날**. 다시 받으면 날짜만 바꾼 새 이름으로 두면 최신만 적재된다 (옛 파일은 자동 제외, ID 유지).
3. 인명·`(1)`·`최종`·`수정` 같은 꼬리 금지, `.xlsx` 만.
4. 한 파일에 여러 파트가 들면 묶음 약칭(MD)을 쓰고 `parts.yaml file_bundles` 에 나눌 Tool ID 접두어를 적는다.
5. Tool ID 는 `<파트약칭>-<번호>` (예 `MDC-1`). 번호 앞 0 은 있어도 없어도 된다 — 단 기본정보·입출력 두 시트에서 같게 (M3.1 #18 에서 `1`=`01` 로 흡수 예정).
