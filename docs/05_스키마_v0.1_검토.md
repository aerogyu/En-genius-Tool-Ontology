# 05. 스키마 v0.1 검토 기록 (M1)

M1(스키마 v0.1)을 끝내며 한 검토와 그 결과. 고친 것은 코드·테스트에 반영됐고, **미결 사항은 M3·M4 착수 전에 Leo 결정이 필요하다.**

## 1. 산출물

| 파일 | 내용 |
|---|---|
| `schema/engenius_tool.yaml` | LinkML 스키마 마스터 v0.1.0 — 클래스 7종 + 파생 provenance 믹스인, 양식 선택지 21 + 스키마 열거형 4 |
| `schema/engenius_tool_dataset.yaml` | Pydantic 검증용 컨테이너 (RDF 로 직렬화하지 않음) |
| `schema/generated/` | OWL, SHACL, 양식 매핑표(`form_mapping.md`), gen-doc 문서 — `python -m engenius_onto schema` 로 생성, `--check` 로 드리프트 검사 |
| `src/engenius_onto/schema_model.py` | 생성된 Pydantic 클래스 |
| `src/engenius_onto/shacl_check.py` | Fuseki 배포본 jar 의 Jena SHACL 로 검증 실행 |

M1 완료 기준(docs/03): `linkml lint` 0건 · 양식 매핑 누락 0 (SW기본정보 33열 = 적재 32 + 제외 1, SW입출력 13열 = 적재 12 + 제외 1) · 생성 OWL 이 추론기에서 열림(아래 3장). 설계 문서와 달라진 점은 docs/02 12장.

## 2. 검토 방법

- 만들면서 직접 잡은 결함 3건: `Field` 클래스명이 생성 Pydantic 에서 `pydantic.Field` 를 덮어씀, `@ko` 이름이 SHACL `xsd:string` 에 전부 걸림, OWL 이 표준 어휘(rdfs:label 등)를 데이터 속성으로 재정의.
- 독립 검토 5관점 (설계 명세 적합성 · 후속 구현 가능성 · 기술 정확성 · 양식 충실도 · 상위 원칙·보안) + 관점마다 반박 검증자. **지적 55건 → 반박 통과 40건** (major 2, minor 38), 반박 15건.
- 검증자들은 주장을 실행으로 확인했다: HermiT 추론기(owlready2 동봉, 일회성 — 저장소 의존성 아님), Jena SHACL, Xerces XSD 정규식, 개발 PC 한국어 Excel(COM) 셀 변환.

## 3. 고친 것

| 지적 | 내용 | 조치 | 확인 |
|---|---|---|---|
| GOV-1·TECH-1·SPEC-6 (major) | LinkML identifier 가 `eg:id` 데이터 속성이 되어, OWL 에서 `xsd:anyURI ∩ xsd:string` (서로소) 제약 때문에 **핵심 7개 클래스가 전부 충족 불가**, SHACL 에서는 `eg:id` 트리플이 없어 ID 검사가 **무효** | OWL 에서 `eg:id` 제거, SHACL 은 노드 IRI 자체에 패턴(`^http://en-genius.local/id/FLD-[0-9]{3}$` 등) | HermiT: 수정 전 분류 불가(오류 중단) → 수정 후 **일관·충족 불가 0**. Jena SHACL: 잘못된 ID IRI 위반 검출 |
| TECH-2 | OWL `xsd:pattern` 에 `^…$` 앵커 — XSD 정규식에서는 일반 문자라 모든 값 거부 | 앵커 제거, `\d`→`[0-9]`, 문자 클래스 `-` 이스케이프 (HermiT 가 받는 문법) | HermiT: 선택지 밖 값 `CLI만`·만료 `2027/03` 인스턴스를 **비일관으로 검출**, 정상 인스턴스는 일관 |
| TECH-6 | OWL 미선언 주석 속성 13개, `prov:wasDerivedFrom` 에 전역 range, 대상 없는 `skos:exactMatch` | 주석 속성 선언, 외부 속성 range 는 Derived 의 국소 제약으로, 고아 제거, `owl:versionInfo` | 테스트: 미선언 0·고아 빈 노드 0 |
| GOV-9·TECH-4·SPEC-5·DOWN-5 | 컨테이너 스키마 접두어 누락(직렬화 시 `rdfs:` 깨진 IRI), `Dataset.feeds` 가 `eg:feeds` 와 같은 슬롯 | 접두어 추가 + 본 스키마와 일치 검사, 컨테이너는 `egds:` 네임스페이스, `derived_feeds` 로 개명, "RDF 로 직렬화하지 않음" 명시 | `schema` 점검 항목 추가 |
| TECH-5·DOWN-6 | SHACL 이 한 번도 실제 엔진으로 실행된 적 없음 | `shacl_check` + 합성 survey∪derived 로 적합 1건·위반 11종 테스트 | 67 테스트 통과 |
| SPEC-11·TECH-7 | 이름 SHACL 이 `@ko` 를 강제하지 않음 | `sh:languageIn ("ko")` | Jena: `@en` 단독 이름 위반 |
| SPEC-10·GOV-4 | "config 하나로 네임스페이스 일괄 변경" 이 구현과 다름 | `config/namespaces.yaml` 삭제, 정본 = 스키마 prefixes (코드가 거기서 읽음), docs/02 4장 문구 수정 | 테스트 |
| TECH-9 | 점검 구멍: 잔존 파일 검사가 docs/ 만, 제외 주석 형식 오류 시 예외, 매핑·제외 중복 미검출 | 생성물 폴더 전체 검사, 형식 오류는 문제로 보고, 중복 검출 | |
| FORM-7 | 헤더 정규화가 전각 `＊` 를 못 맞춤 | NFKC 후 비교 | 테스트 |
| FORM-9·DOWN-8 | 확장자 패턴이 `tar.gz` 를 거부 | 다중 점 허용 (괄호 주석은 계속 거부 — 정규화 대상) | 테스트 |
| SPEC-12 | 파일명 슬롯에 경로가 들어가도 통과 | 경로 구분자·드라이브 문자 금지 패턴 | 테스트 |
| SPEC-1·DOWN-2 | `Feed.grade` 설명이 "변환 구간에도 매긴다" — 변환 구간엔 Feed 가 없음 | 설명을 수기 연결 Feed 로 한정, 변환 구간은 미결 D1 | |
| SPEC-4·GOV-8 | 상태 어휘가 상위 스키마 §6 인용과 다름, 기본값 없음 | 대응 설명(통합됨≈대체됨), 기본값 활성 | |
| DOWN-7 | `partner_unresolved` 저장값 미정 | 정규화 키로 저장한다고 명시 (원문은 partner_raw) | |

한계: Protégé 자체는 실행하지 않았다 — 같은 HermiT 추론기를 owlready2 로 돌렸다. Protégé 에서 여는 확인은 Leo 몫으로 남긴다.

## 5. 반박된 지적 (참고)

15건 — 설계 문서가 정한 결정이거나(예: 담당 부서·분류를 노드로 둔 것, 보안등급 슬롯 하나, provenance 범위), 근거가 틀렸거나(예: Feed 의 방향별 전달 방법은 from_io/to_io 로 알 수 있음), 검토표(보고서)로 충분한 것(예: CQ10 통합 후보). 원문은 워크플로 기록에 있다.
