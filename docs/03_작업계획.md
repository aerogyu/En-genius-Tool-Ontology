# 03. 작업 계획 (M0 ~ M6)

원칙: **좁게, 끝까지.** 넓게 벌리기보다 합성 데이터로 적재 → 도출 → 보고서까지 한 번 관통하는 것이 먼저다.
각 마일스톤을 시작할 때 할 일을 짧게 제안하고, 끝나면 완료 기준으로 스스로 점검한 뒤 CLAUDE.md의 '현재 상태'를 갱신한다.

## M0. 환경·골격

- git 초기화, `.gitignore` 확인 (`data/real/`, `output/`, `offline/wheels/`, `.venv/`, `.env`)
- 가상환경, `requirements.txt`(런타임)와 `requirements-dev.txt`(pytest 등 개발용) 분리
- 로컬에 Java 17 이상과 Fuseki(Jena 5 계열) 설치, `config/fuseki/`에 TDB2 데이터셋 `engenius` 설정(unionDefaultGraph) 작성 후 기동 확인
- `src/engenius_onto/` 패키지와 CLI 골격: `load`, `derive`, `report`, `push`, `query`, `all`

**완료 기준**: `python -m engenius_onto --help` 동작 / Fuseki에 빈 `engenius` 데이터셋이 뜸 / `pytest` 통과(골격 테스트)

**완료 기준**: `linkml lint` 결과 검토 완료 / 생성된 OWL이 Protégé에서 열림 / 매핑 누락 0
**여기서 멈추고** 클래스 구조와 매핑표를 Leo에게 보여준다.

## M2. 합성 데이터와 골든 결과

`reference/SW조사양식_EnGenius_v1.0.xlsx`를 복사해 채운 합성 조사 파일을 **시드 고정 스크립트**로 만든다.
- 규모: 분야 8개 내외(성능, 압축기, 터빈, 연소기, 2차유로(SAS), 구조, 제어, 시험), 툴사용 35건 내외, 고유 툴 25개 내외
- 툴 이름: 공개 상용 툴(CATIA V5, ANSYS Fluent, ANSYS Mechanical, STAR-CCM+, MATLAB, Excel, Tecplot, NASTRAN, LabVIEW 등)과 가상 사내 툴(`가상-1D네트워크`, `가상-성능덱` 등). 실제 사내 툴명은 쓰지 않는다.
- 템플릿 예시 행(SW기본정보 4행, SW입출력 4~6행)은 **그대로 남겨** 제외 로직을 시험한다.

**심어둘 사례 (골든 결과 `tests/golden/expected.yaml`에 기대값으로 기록)**

| 번호 | 사례 | 기대 검출 |
|---|---|---|
| P1 | 3단 수기 체인: 가상-성능덱 → (수기) → Excel 상관식 → (수기) → 가상-1D네트워크. 최소 한 구간은 양쪽 CLI 가능 | CQ02·CQ03, 등급 A 1건 이상 |

| P4 | 고립 2종: 입출력 행이 없는 툴사용 1건, 입출력은 있으나 어디와도 안 맞는 툴사용 1건 | CQ05 두 유형 각각 |

## M5. 반입 패키지

- 먼저 Leo에게 사내 OS와 파이썬 버전을 확인한다.
- `offline/wheels/`: 사내와 같은 OS·파이썬 버전 기준으로 받은 wheel 전체, 버전을 고정한 `requirements.lock`
- Fuseki 설정 파일, 실행 스크립트(Windows .bat / Linux .sh), 합성 샘플 데이터
- `README_사내실행.md`: 한국어 단계별 안내 — Java 설치 확인 → Fuseki 기동 → 가상환경 → 오프라인 설치 → `data/real/`에 실제 조사 파일 두기 → 실행 → 보고서 확인 → Fuseki에서 질의. 실제 양식의 헤더·선택지가 다를 때 `config/`만 고치는 방법 포함.
- 패키지에는 합성 레지스트리를 넣지 않는다 (사내는 빈 레지스트리로 시작).

**완료 기준**: 새 가상환경에서 `pip install --no-index --find-links offline/wheels -r requirements.lock` 성공 / README만 보고 처음부터 끝까지 재현 / 패키지 안에 실데이터·사내 정보 없음 확인

## M6. 에이전트 준비 — Leo 승인 후 착수

- MCP 서버 `ontology-query`: 읽기 전용 질의 함수 (`docs/02` 11장). 템플릿 SPARQL만, 입력값 검증.
- LangGraph 최소 에이전트: langchain-mcp-adapters로 MCP 도구 로드, HITL 승인 중단점, LLM은 OpenAI 호환 `base_url` 설정. 테스트는 가짜 LLM으로 외부 호출 없이.
- 툴 래핑 패턴 예시 (가상 솔버): 검증된 입력 템플릿 + 파라미터 채움 + 실행 + 입력·결과 파일 보존 + 엔지니어 승인 단계. 사내에서 CQ03 상위 구간을 실제로 감쌀 때의 본보기.
- 반입 목록 갱신 (`docs/04`).

**완료 기준**: 외부 네트워크 없이 테스트 통과 / 에이전트가 "가상-1D네트워크의 상류 수기 구간을 보여줘" 같은 요청을 질의 함수로만 처리
